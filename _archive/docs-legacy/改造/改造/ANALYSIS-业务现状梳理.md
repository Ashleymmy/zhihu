## 一、业务现状确认

### 1.1 与业务方确认的事实

根据与业务和数据提供方的确认，实际情况如下：

| 接口/数据类型 | 官方提供状态 | 实际可用性 | 备注 |
|------------|------------|----------|------|
| **作品审核状态接口** | ❌ 无效 | 不可用 | 无法通过 API 查询 |
| **佣金结算类接口** | ❌ 无效 | 不可用 | 不提供实时 API |
| **转化和订单数据接口** | ❌ 无效 | 不可用 | 不提供实时 API |
| **实施回传状态数据接口** | ❌ 无效 | 不可用 | 不提供实时 API |
| **创建推广计划接口** | ✅ 有效 | 可用 | 唯一完整的写入链路 |
| **创建和绑定关键词接口** | ✅ 有效 | 可用 | 唯一完整的写入链路 |
| **收益、资金、转化、订单数据** | 📧 邮件提供 | 每日定时 | 人工或半自动获取 |

### 1.2 数据提供方式

**知乎官方 → 代理商** 的数据传递方式：

```
┌─────────────┐
│  知乎官方    │
└──────┬──────┘
       │
       │ 每日邮件发送（汇总数据）
       ▼
┌─────────────┐
│  代理商邮箱  │ ← 收益、订单、转化数据（汇总）
└─────────────┘
```

**特点**：
- 数据以 **汇总形式** 提供（不区分代理商内部的团长/达人）
- **按关键词维度** 提供搜索量和转化量
- **无细粒度归因信息**（不知道是哪个达人产生的转化）

## 二、当前系统实现 vs 真实业务

### 2.1 当前系统假设（错误）

当前代码实现基于以下假设：

| 模块 | 当前代码假设 | 实际业务情况 | 差距 |
|-----|-----------|-----------|-----|
| **审核状态同步** | 通过 API 每日自动同步 | ❌ API 无效，无法获取 | 功能无效 |
| **收益数据拉取** | 通过 API 自动拉取 | ❌ API 无效，靠邮件 | 需人工导入 |

| **达人归因** | 假设知乎提供达人级数据 | ❌ 只提供关键词汇总 | 缺失归因逻辑 |

## 三、核心问题识别

### 3.1 问题一：关键词归因的一对多关系

**问题描述**：

```
代理商创建关键词 → 唯一性（不冲突）✅
  ↓
团长使用关键词 → 可以独占（唯一性隔离）✅
  ↓
达人使用关键词 → 可以复用团长/代理商关键词 ❌ 一对多
  ↓
散户达人使用关键词 → 可以复用已有关键词 ❌ 一对多
```

**数据链示例**：

```
关键词：知乎推广工具

代理商层级：知乎推广工具 (plan_id: P001)
  ├─ 团长A：知乎推广工具 (复用 P001)
  │   ├─ 达人A1：使用 "知乎推广工具" 发布作品
  │   ├─ 达人A2：使用 "知乎推广工具" 发布作品
  │   └─ 达人A3：使用 "知乎推广工具" 发布作品
  └─ 团长B：知乎推广工具 (复用 P001)
      ├─ 达人B1：使用 "知乎推广工具" 发布作品
      └─ 达人B2：使用 "知乎推广工具" 发布作品

散户达人 C：使用 "知乎推广工具" 发布作品
```

**知乎官方提供的数据**（邮件）：

```
关键词: 知乎推广工具
搜索量: 1000
转化量: 50
收益: 5000 元
```

**问题**：如何将这 5000 元拆分到不同团长和达人？

### 3.2 问题二：邮件数据的自动化获取

**现状**：
- 知乎官方每天通过邮件发送数据（Excel/CSV 附件？）
- 当前系统假设 API 自动拉取（实际不可行）

**问题**：
1. 邮件格式是否标准化？（Excel? CSV? PDF?）
2. 是否有固定发件人/主题/时间？
3. 能否通过 IMAP/POP3 自动读取邮箱？
4. 数据格式是否固定？（字段、列名、数据类型）

### 3.3 问题三：必须人工介入的环节

需要明确哪些环节 **必须** 人工参与：

| 环节 | 是否可自动化 | 人工介入原因 |
|-----|-----------|------------|
| 创建推广计划 | ✅ 可自动 | API 可用 |
| 创建关键词 | ✅ 可自动 | API 可用 |
| 下载邮件数据 | ❓ 待确认 | 取决于邮件格式 |
| 数据导入系统 | ❓ 待确认 | 取决于数据标准化程度 |
| 收益分配规则设置 | ❌ 必须人工 | 业务规则复杂 |
| 收益审核确认 | ❌ 必须人工 | 避免错误分配 |
| 异常数据核对 | ❌ 必须人工 | 数据质量问题 |

## 五、关键约束条件

### 5.1 技术约束

| 约束 | 描述 | 影响 |
|-----|------|------|
| **知乎 API 限制** | 只能写入计划和关键词，无法读取收益/转化 | 必须依赖邮件数据 |
| **数据粒度** | 知乎只提供关键词级汇总，无达人级数据 | 必须自建归因逻辑 |
| **关键词复用** | 多个达人可使用同一关键词 | 无法通过关键词直接归因 |
| **邮件格式** | 未知邮件数据的结构化程度 | 影响自动化程度 |

### 5.2 业务约束

| 约束 | 描述 | 影响 |
|-----|------|------|
| **归因准确性** | 收益分配必须准确，避免纠纷 | 必须有人工审核环节 |
| **隔离要求** | 团长/达人的数据必须隔离 | 需要细粒度权限控制 |
| **关键词唯一性** | 代理商级别关键词唯一 | 可以作为归因的基础维度 |
| **团长独占性** | 团长可以独占关键词（可选） | 影响归因规则设计 |

## 六、待确认事项

### 6.1 邮件数据相关（优先级：🔴 高）

需要与业务方确认：

1. **邮件格式**
   - [ ] 邮件附件是什么格式？（Excel / CSV / JSON / PDF?）
   - [ ] 是否有固定的发件人和主题？
   - [ ] 发送时间是否固定？（例如每天早上 8 点）
   - [ ] 是否所有数据都在一封邮件里？

2. **数据结构**
   - [ ] 提供一份真实邮件数据的样本（脱敏版）
   - [ ] 数据包含哪些字段？（日期、关键词、搜索量、转化量、收益？）
   - [ ] 是否有订单明细？还是只有汇总数据？
   - [ ] 数据是否包含历史数据？还是只有昨日新增？

3. **数据质量**
   - [ ] 数据是否完整？（会不会有缺失）
   - [ ] 数据是否准确？（是否需要人工核对）
   - [ ] 是否有异常数据的处理流程？

### 6.2 关键词与归因相关（优先级：🔴 高）

需要与业务方确认：

1. **关键词使用规则**
   - [ ] 达人使用关键词时，是否需要系统内"申请"或"绑定"？
   - [ ] 达人发布作品时，是否在系统内登记关键词？
   - [ ] 散户达人如何管理？是否在系统内？

2. **归因规则**
   - [ ] 如果多个达人使用同一关键词，如何分配收益？
     - 按作品数量平均分？
     - 按作品质量（浏览量）加权分？
     - 人工指定比例？
   - [ ] 团长是否参与收益分配？分配比例如何确定？
   - [ ] 散户达人的收益如何处理？

3. **作品登记**
   - [ ] 达人发布作品后，是否必须在系统内登记？
   - [ ] 作品登记时是否填写使用的关键词？
   - [ ] 作品的平台（抖音/小红书）、链接、发布时间是否记录？

### 6.3 人工环节相关（优先级：🟡 中）

需要与业务方确认：

1. **数据导入**
   - [ ] 当前如何处理邮件数据？（手动下载 → 手动导入？）
   - [ ] 导入频率？（每天？每周？）
   - [ ] 是否需要数据清洗或校验？

2. **收益审核**
   - [ ] 谁负责审核收益分配？（管理员？团长？）
   - [ ] 审核流程是怎样的？
   - [ ] 是否需要多级审核？

3. **异常处理**
   - [ ] 如何处理数据不匹配的情况？（邮件数据 vs 系统记录）
   - [ ] 如何处理归因冲突？
   - [ ] 是否需要申诉机制？
