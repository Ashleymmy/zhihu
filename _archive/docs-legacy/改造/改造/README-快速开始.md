## 💡 常见问题

### Q1：定价规则在哪里配置？

**A**：在 `pricing_rules` 表中配置。参考现有的 `relay.service.ts`。

P0 阶段假设定价规则已配置好：
- 达人规则：60% percentage
- 团长规则：10% percentage

### Q2：归因引擎如何对接现有定价体系？

**A**：通过 `settlement_batches` + `settlement_items`。

```
归因收益 → settlement_items.source_amount
         ↓
定价规则应用（复用 approveBatch）
         ↓
earnings.amount（最终入账）
```

详见：[整合方案](./SOLUTION-归因引擎与定价策略整合方案.md#五实现方案)

### Q3：P0 阶段不做哪些功能？

**A**：以下功能留到 P1/P2：

- ❌ 数据预览（直接导入）
- ❌ 去重检测（允许重复）
- ❌ 作品审核（直接通过）
- ❌ 置信度评估（全部自动）
- ❌ 人工调整（没有审核界面）
- ❌ IMAP 自动收取（手动上传）

### Q4：如果遇到需求变更怎么办？

**A**：模块化设计，每个模块可独立替换。

- 如果归因算法需要调整 → 只改 `processAttribution.ts`
- 如果定价规则需要调整 → 只改 `pricing_rules` 表配置
- 如果 P1 功能不需要了 → 直接不做

### Q5：测试数据怎么准备？

**A**：准备 3 个角色的测试账号：

```sql
-- 管理员
INSERT INTO users (username, role) VALUES ('admin', 'admin');

-- 团长
INSERT INTO users (username, role) VALUES ('leader_x', 'leader');

-- 达人（团长 X 旗下）
INSERT INTO users (username, role, parent_id) 
VALUES ('creator_a', 'creator', [leader_x_id]);

INSERT INTO users (username, role, parent_id) 
VALUES ('creator_b', 'creator', [leader_x_id]);

-- 散户达人
INSERT INTO users (username, role) 
VALUES ('creator_c', 'creator');
```
