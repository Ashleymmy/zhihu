## 零、通用约定

### 服务域名

```
https://open.zhihu.com
```

所有接口路径均以 `/alliance/api/` 开头。

> **前端不直连此域名**。开发环境走 Vite proxy，生产环境走自建 BFF。
> 原因见 [01-架构设计.md § 八、安全边界](./01-架构设计.md#八安全边界)。

### 四种传参形式

文档中每个参数都标注了「传参形式」，共四种，对应的代码写法不同：

| 传参形式 | 含义 | Axios 写法 |
| --- | --- | --- |
| `Body JSON` | 放在请求体，JSON 格式 | `http.post(url, { ...params })` |
| `Query Param` | 放在 URL 查询串 | `http.get(url, { params })` |
| `Form-Data` | 放在表单，用于文件上传 | `FormData` + `Content-Type: multipart/form-data` |
| `Url Param` | 路径参数，拼在 URL 里 | `http.put(\`${url}/${id}\`, body)` |
| `Header` | 请求头 | `{ headers: { ... } }` |

### 通用鉴权参数

除特别说明外，每个接口都需要这三个参数（传参形式跟随该接口的主要形式）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `access_token` | STRING | 是 | 开发者 Token |
| `timestamp` | INT | 是 | 请求时刻**秒级**时间戳 |
| `signature` | STRING | 是 | 接口签名，算法见 04 文档 |

### 统一响应结构

**成功响应：**

```json
{
  "success": true,
  "msg": "创建成功",
  "data": { }
}
```

**失败响应（注意：HTTP 状态码可能仍为 200）：**

```json
{
  "error": {
    "code": 400400,
    "name": "OpenApiParamError",
    "message": "timestamp 无效"
  }
}
```

> ⚠️ **判断成败不能只看 HTTP 状态码**，必须检查 body 里是否存在 `error` 字段。
> 这一逻辑已在 `infra/http/interceptor-error.ts` 统一处理。

**三个例外情况：**

| 例外 | 接口 | 说明 |
| --- | --- | --- |
| 无 `data` 包装 | 查询榜单列表（§ 9.1） | 成功时直接返回数组 |
| 无 `data` 包装 | 查询榜单内容详情（§ 9.3） | 成功时直接返回对象 |
| 文件流 | 查询批量任务结果（§ 6.1） | `Content-Type: application/octet-stream` |

### 统一分页结构

带分页的接口返回结构如下。注意**不同接口的字段完整度不一致**：

```json
{
  "pagination": {
    "is_first": true,
    "is_end": false,
    "offset": 0,
    "limit": 10,
    "total": 11
  }
}
```

| 字段 | 类型 | 说明 | 出现范围 |
| --- | --- | --- | --- |
| `total` | INT | 总条数 | 所有分页接口 |
| `offset` | INT | 当前偏移量 | 所有分页接口 |
| `limit` | INT | 当前每页条数 | 所有分页接口 |
| `is_first` | BOOL | 是否第一页 | 部分接口 |
| `is_end` | BOOL | 是否最后一页 | 部分接口 |

> 前端实现建议：定义统一的 `Pagination` 类型，`is_first` / `is_end` 设为可选，
> 判断「是否还有下一页」时用 `offset + limit < total` 兜底，不依赖 `is_end`。

### 分页参数

| 参数 | 类型 | 必填 | 默认值 | 是否参与签名 |
| --- | --- | :---: | --- | :---: |
| `offset` | INT | 否 | `0` | ❌ 不参与 |
| `limit` | INT | 否 | 见各接口，多为 `10`，个别为 `100` | ❌ 不参与 |

### 日配额限制

每个开发者账号**每日接口调用总次数**有上限，**所有接口共享同一配额**。
超限后当天禁止访问。配额值与扩容需咨询知乎运营。

工程约束见 [README § 红线三](./README.md)。

### 2.2 作品一级分类 `composition_type`

| 值 | 名称 |
| :---: | --- |
| `0` | 其他 |
| `1` | 图文 |
| `2` | 视频 |

> **v1 接口的取值不同**：v1 的 `composition_type` 是 `0-其他 1-图文 2-视频 3-截图`，
> 多了一个 `3-截图`。v2 取消了 `3`，把「截屏」下移为图文的二级分类。
> 这是迁移时容易忽略的差异。

### 2.3 作品二级分类 `composition_sub_type`

**必须与一级分类合法组合，否则操作失败。**

| 一级分类 | 允许的二级分类 |
| --- | --- |
| `1` 图文 | `1` 实拍、`2` live图、`3` 截屏、`4` 漫画 |
| `2` 视频 | `5` 表情包解说、`6` 真人演绎、`7` 猫meme、`8` 漫剧、`9` 解压、`10` 滚屏 |
| `0` 其他 | `11` 其他 |

```typescript
/** 作品一级分类 */
export enum CompositionType {
  Other = 0,
  ImageText = 1,
  Video = 2,
}

/** 作品二级分类 */
export enum CompositionSubType {
  RealShot = 1,        // 实拍
  LivePhoto = 2,       // live图
  Screenshot = 3,      // 截屏
  Comic = 4,           // 漫画
  StickerCommentary = 5,  // 表情包解说
  RealPerson = 6,      // 真人演绎
  CatMeme = 7,         // 猫meme
  ComicDrama = 8,      // 漫剧
  Relaxing = 9,        // 解压
  ScrollScreen = 10,   // 滚屏
  Other = 11,          // 其他
}

/** 一级分类 → 合法二级分类的映射。用于级联选择器与提交前校验 */
export const VALID_SUB_TYPE_MAP: Record<CompositionType, CompositionSubType[]> = {
  [CompositionType.ImageText]: [1, 2, 3, 4],
  [CompositionType.Video]: [5, 6, 7, 8, 9, 10],
  [CompositionType.Other]: [11],
}

/** 二级分类的中文名 */
export const SUB_TYPE_LABELS: Record<CompositionSubType, string> = {
  1: '实拍', 2: 'live图', 3: '截屏', 4: '漫画',
  5: '表情包解说', 6: '真人演绎', 7: '猫meme', 8: '漫剧', 9: '解压', 10: '滚屏',
  11: '其他',
}

/** 校验一二级分类组合是否合法 */
export function isValidCompositionTypeCombo(
  type: CompositionType,
  subType: CompositionSubType,
): boolean {
  return VALID_SUB_TYPE_MAP[type]?.includes(subType) ?? false
}
```

## 三、推广计划管理

推广计划是「一个关键词」的推广单元，挂在某个「推广任务」之下。

**依赖关系**：创建计划前需要先拿到 `task_id`（§ 7.1）和 `channel_id`（§ 5.1）。

### 3.1 单个创建推广计划

```
POST https://open.zhihu.com/alliance/api/popularize_plan
```

**请求参数**（全部 `Body JSON`）

| 参数 | 类型 | 必填 | 参与签名 | 说明 |
| --- | --- | :---: | :---: | --- |
| `task_id` | STRING | 是 | ✅ | 推广任务 id，由 § 7.1 获取 |
| `channel_id` | STRING | 是 | ✅ | 渠道 id，由 § 5.1 获取 |

**失败响应**

**注意事项**

**服务层实现**

```typescript
// src/services/batch-task.service.ts
/**
 * 查询批量任务结果
 *
 * 接口：GET /alliance/api/get_batch_task_result/:batch_task_id
 * 文档：docs/03-接口文档.md § 6.1
 *
 * ⚠️ 返回文件流，必须指定 responseType: 'blob'。
 * 任务未完成时接口报错，调用方应捕获并重试，不要视为最终失败。
 */
export async function getBatchTaskResult(batchTaskId: string): Promise<Blob> {

}

/**
 * 触发浏览器下载 Blob。
 *
 * 注意必须 revokeObjectURL，否则 Blob 一直占内存不释放。
 */
export function downloadBlob(blob: Blob, filename: string): void {
  const url = URL.createObjectURL(blob)
  const anchor = document.createElement('a')
  anchor.href = url
  anchor.download = filename
  document.body.appendChild(anchor)
  anchor.click()
  document.body.removeChild(anchor)
  URL.revokeObjectURL(url)
}

- **推荐所有上传场景统一走这个接口**

**服务层实现**

```typescript
// src/services/basic.service.ts
/**
 * 通用文件上传
 *
 * 接口：POST /alliance/api/basic/file_upload
 * 文档：docs/03-接口文档.md § 15.1
 *
 * 前端应先校验格式与大小，避免无效请求消耗日配额。
 */
const ALLOWED_IMAGE_TYPES = ['image/jpeg', 'image/png'] as const
const MAX_IMAGE_SIZE_BYTES = 2 * 1024 * 1024   // 2 MB

export function uploadFile(file: File, fileType: FileType = FileType.Image) {
  if (fileType === FileType.Image) {
    if (!ALLOWED_IMAGE_TYPES.includes(file.type as typeof ALLOWED_IMAGE_TYPES[number])) {
      throw new Error('只支持 jpeg 或 png 格式的图片')
    }
    if (file.size > MAX_IMAGE_SIZE_BYTES) {
      throw new Error(`图片不能超过 2 MB，当前 ${(file.size / 1024 / 1024).toFixed(2)} MB`)
    }
  }

  const formData = new FormData()
  formData.append('file_type', String(fileType))
  formData.append('file', file)

  return http.post<UploadFileResponse>(API_PATHS.FILE_UPLOAD, formData, {
    headers: {
      'X-Requested-With': 'openApi',
      'Content-Type': 'multipart/form-data',
    },
  })
}
```
