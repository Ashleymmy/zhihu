# 前端核对意见与实施回执（对 IMPLEMENTATION.md）

核对日期 2026-11-04。核对人为 Web UI 实施侧。依据后端《v3 原型与真实实现逐功能对照清单》（169 项）逐条核对。本文只回答三件事：哪些接受、哪些改、先做什么；后端能力需求按优先级回执。

## 一、总体态度

**全面采纳后端审计结论**，包括对我方原稿（27112de 版 IMPLEMENTATION.md）的 6 处纠正：

| 后端纠正 | 我方原稿误判 | 现结论 |
| --- | --- | --- |
| COR-1-03 / OM08 | 「入团申请无接口、业务无申请审批流，不做」 | **错**。独立达人申请/撤回、团长审批/拒绝、已有账号接受邀请三条路径均有实现（M-R01/M-G05），接回原型 |
| COR-1-04 / COR-2-03 | 「TeamView 是员工向，团长团队页需新建」 | **改为适配**。MemberManagementView 已有团长分支，做视图重排与字段补充，不新建第二套 |
| COR-1-05 | 「IncomeView 只有明细，四类汇总均要补」 | **不准确**。PlatformIncome 已有本期/已确认/待确认卡、项目业绩汇总、筛选与抽屉；要补的是分类归属（邀请/激励待规则） |
| COR-2-01 / COR-3-08 | 「insights-api 补 byProject 后即可点亮员工金额卡」 | **过于乐观**。insights 只有成员收益统计；上游收入/平台留存/实际付款各自缺账源口径（BE-08），且运营金额有权限冲突 |
| COR-3-01 | 「财务总览映射 FinanceView 并入首页即可」 | **错**。FinanceView 是五步账期工作区入口，财务首页需另列聚合契约（F-H01） |
| COR-2-10 / AU04 | 原型承诺「日志不可删除、保留 3 年」 | **与现有 7–365 天清理接口冲突**，列入业务决策，原型文案先改 |

## 四、原型（v3/index.html）需要修正的地方

原型 30 项规则冲突中，由我方负责修正原型的部分：

1. 运营总览：金额主卡、上游收入趋势、团队排行金额、实时动态金额、数据大屏入口 → 运营版收窄为**非金额业务指标**（单量/件数/人数），金额版归完整管理员/财务
2. 达人/团长收益页：「通过即打款、实时到账、微信零钱已到账」→ 改为「审核通过 → 财务登记发放 → 已发放（凭证）」的真实链路文案
3. 审计页：「不可删除、保留 3 年」→ 改为「保留策略待确认」（现有 7–365 天清理并存）
4. 达人右栏/成员页：作品数、合格率、直邀成员个人收益金额 → 移除（成员不可见）
5. 激励卡（600/1000、92/94/80%）：标注「演示数值，规则未确认」，不进入真实发放语义
6. 晋升环 3/4：改「参考指标」展示，不出达标结论
7. 拉活单位：统一「个」（原型个别处写「次」）
