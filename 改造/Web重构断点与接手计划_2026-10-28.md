## 5. 接手计划

原则：**这个 worktree 只做 Web**。需要新后端接口时，在主线开独立分支做，Web 分支定期合主线。

### 第 0 步：固定现场（半天）

1. 把文档整理单独提交：已暂存的 54 个 rename + `AGENTS.md` / 规范 / 两个 README + `prototypes/baseline/`。一个提交，信息 `docs: archive legacy documents and record the web redesign baseline`。
2. 把 insights 半成品挪走：`insights-routes.ts`、`routes.ts` 的挂载、`relation-routes.ts` 的 export、测试 +13 行，一起放到新分支 `claude/insights-api`（基于 origin/main），在那边补完、验收后走主线。本分支工作区清空。
3. `git branch --set-upstream-to`，推送分支，避免再出现“本地孤儿分支”。

### 第 1 步：合并主线（1–2 天）

1. `git merge origin/main`（不 rebase，19 个提交里有被 cherry-pick 的，rebase 会制造第二份）。
2. 冲突策略：
   - `server/src/core/relation-routes.ts`、`member-relations.ts`、`staff.ts`、`index.ts`、`shutdown.ts`、`services/*`：**取主线**，然后手工叠回本分支的 `/members/:id/transfer`、`/handover`、`/demote`、`/settings` 四组接口，并让它们走主线新的“复核操作”路径（11730cf 的模式），不要绕开。
   - `apps/`、`packages/`：**取本分支**，再对照主线改动把新增字段（随机公开 ID、成员历史、导出入口）接进来。
   - `access.ts`、`platform-pages.ts`：两边都加了路由，逐行合并。
   - 3 个集成测试：两边都保留，跑通为准。
3. 验证全套：`cd server && npm run typecheck` → Docker 集成测试（至少 `tests/opc`、`tests/attribution`）→ `pnpm typecheck && pnpm build` → `npm run demo:review` 四个角色登录。
4. 这一步做完就是新的基点，之后每周合一次主线。
