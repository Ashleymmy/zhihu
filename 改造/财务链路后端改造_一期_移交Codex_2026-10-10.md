# 财务链路后端改造（一期）· 前后端接口契约

> 2026-10-10 评审修订，已获准实施。基线 main 6968be5；后端分支 codex/finance-phase-one。
> 本版替代旧稿中的 501 条拒绝、异议唯一键、银行卡必填要求。后端已实现并通过下述回归，前端据此联调。

## 1. 范围

全职责管理员在同一流程完成操作，不新增转交或审批；其他岗位的后端隔离保留。三层账、旧 earnings/relay 资金链、小程序页面保持原范围。已确认账使用更正行、金额沿用 BigInt 四位小数。LEGACY_SHARED 等待另行确认，不在本期自动改归属或排除收入。

付款实际在线下微信/支付宝完成。系统只登记已线下发放，不调用支付通道、不验证外部到账。收款账号、真实姓名、银行信息、流水号、凭证、备注均选填。

## 2. 通用约定

- 模块根路径 /api/v1/modules/zhihu；资金根路径 /api/v1/core/finance。
- 模块请求带 projectId/accountId；资金请求另带 moduleId。ID、金额和数量均为字符串，JSON 为 camelCase。
- 新写操作带 requestKey（8–128 位字母、数字、下划线、点、横线）。同键同内容返回首次回执，不同内容 409。原资金端点允许旧客户端省略，以状态/版本兜底；新客户端应传。
- 同时校验项目、账号、岗位；成员仅查看和操作本人记录。公共核心不能查询知乎模块表。

## 3. B1/B2：一次确认，后台分段

POST /workbench/confirm：scope + {from,to,viewVersion:'2',metricType?,reviewHash,acknowledged:true,requestKey}。

GET /workbench 和 POST /workbench/confirm 必须使用同一日期、viewVersion、metricType。新前端传 viewVersion='2'；省略 metricType 时同时包含拉新/拉活。旧客户端省略 viewVersion 仍按原先只读拉新处理。

返回保留 confirmed/waiting，并增加：{jobId:string|null,status:'done'|'pending'|'failed',total:number,remaining:number,skipped:number,error:string|null}。

- 零条可确认返回 done、jobId=null，不切换 trial、不写启用审计。
- 固定已核对的事实及版本，每个处理事务最多 100 条；不以超过 500 条要求用户缩小日期。
- 小批次同步完成，大批次由 Worker 继续。前端发起一次后轮询，不自行拆成多次独立确认。
- GET /workbench/confirm/:id + scope 返回最新状态；POST 同路径加 /retry，scope + requestKey，恢复失败任务。
- 每条事实的三层记账同事务；重试不重复入账。已完成分段保留，未完成分段可恢复。
- 处理时再次校验版本、作品、修订、金额异议、账号项目及经办人当前权限。数据变化的记录跳过，提示重新核对，不自动确认新金额。
- 首个真正确认金额的事务才切换 trial→enabled。reviewHash 过期返回 409。

## 4. B3：两步上传

POST /workbench/import/preview：multipart file + scope + reportType(new_user|activation，默认 new_user) + requestKey。

返回 {id,duplicate,status,reportType,reportKind,from,to,previewHash,total,invalidRows,page:1,pageSize:100,rows[]}。
rows 含 {id,lineNumber,date,channel,keyword,search,orders,revenue,activations,settlement,agency,riskAssessment,error,status}。

- 只保存原文件/解析行，不生成事实或金额，不自动启用或移动日期边界。离开预览不提交。
- 类型由服务端保存；commit 不接受前端更改解析值或类型。
- 同文件未提交时复用预览，已处理时返回原状态不重复入账，已撤销时创建新上传代次。
- 分页使用现有 GET /imports/:id（page/pageSize）；下载原文件使用 GET /imports/:id/file + scope。
- 无效行保留原因，有效行正常处理。

POST /workbench/import/:id/commit：scope + {previewHash,requestKey}；返回 {id,processed,remaining}。

锁定本范围预览并检查 hash/状态，在确认时处理安全日期边界，再提交和可靠入队。重试返回首次回执；已撤销记录不能复活。旧模板继续按原规则要求重新预览。
旧 POST /workbench/import 保留兼容。/workbench/import/preview 的 split('/')[2] 就是 import，无需扩大前缀授权。

## 5. B4：追溯

GET /attributions/:id/trace 保留现有字段。财务管理员增加 currentSource:[{batchId,rowId,lineNumber,fileName,metrics:string[]}]。
metrics 覆盖 search/orders/revenue/riskAssessment/activations/settlement/agency；同一行贡献多个指标时合并。只取当前已接受来源，无来源返回 []。成员不新增原报表信息，岗位隔离继续保留。

## 6. B5：成员金额异议

与作品归属争议分开，不复用 dispute。仅阻止后续确认，不冻结已确认资金或已线下发放记录。

| 方法/路径 | 输入 | 权限/输出 |
|---|---|---|
| POST /objections | scope + earningLineId 或 factId（二选一）+ detail + requestKey | creator/leader 本人；id |
| GET /objections/mine | scope + page/pageSize/status? | 本人；list,total,page,pageSize |
| GET /objections | scope + page/pageSize/status? | 财务；list,total,page,pageSize |
| POST /objections/:id/reply | scope + reply + requestKey | 财务；id |

- 成员以 GET /api/v1/core/earnings/mine 现有的 id 作为 earningLineId，模块后端校验所属并解析来源；无需前端猜 factId。
- detail/reply 为 1–1000 字，payee/raisedBy 由身份决定。
- 同一事实/成员最多一条 open，使用仅 open 时非 NULL 的生成列唯一键；已回复历史不限，允许再次提问。
- 所有确认入口共用后端异议检查；overview 同步显示 MEMBER_OBJECTION 和 ready=false，不只靠页面拦截。
- 回复改为 replied，解除该项阻塞；其他问题仍阻塞，不自动确认金额。
- 返回关键词、日期、业绩类型和处理时间，成员只看本人内容。已确认钱包余额不因异议归零。

## 7. B6：线下发放留痕

POST /withdrawals：保留 amount/requestKey；增加 payMethod(alipay/wechat/bank，默认 bank)、payAccount。receiverName/bankName/bankAccount/payAccount 全选填，空存 NULL。不要求至少填写一种账号。金额>0、两位小数、余额和防重复校验保留。

POST /funding：保留 hash；reference 选填空存 NULL；增加可选 requestKey，重试返回首次金额。

POST /withdrawals/:id/pay：保留 paidOn、acknowledged(JSON true 或 multipart 'true')；reference/proof/requestKey/remark/payMethod/payAccount 均选填。

- 无凭证可登记；有凭证仍校验大小/类型。空流水存 NULL；非空流水继续唯一。
- 同申请同内容重试返回成功，不重复改变余额；不同内容走更正接口。
- pending/approved 都允许直接登记，保留 offset 校验；原审核接口兼容，不强制多一道审批。
- 不发起转账、不声称验证外部到账。

POST /withdrawals/:id/correct：财务权限；scope + {requestKey,expectedVersion,action:'amend'|'void',reason,paidOn?,reference?,remark?,payMethod?,payAccount?}。

- expectedVersion 来自资金列表 paymentVersion，防并发覆盖。
- amend 改登记资料，不改成员/申请金额；void 撤销错误发放标记，恢复 approved 待登记，不表示外部已退款。
- 保留前后快照、经办审计及原凭证，不改收益账。
- 资金列表/导出增加 payMethod/payAccount；导出包含 pending/approved 并带 status，无需先多做一次审批；列表增加 paymentVersion/paidBy/paidAt；无凭证查询仍 404。
- GET /withdrawals/:id/history + scope 返回登记更正历史（本人或财务可看，运营不可看）。
