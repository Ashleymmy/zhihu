# OPC 三端操作简化改造计划（待审核）

版本：V1.0  
日期：2026-09-13  
状态：仅供审核；审核通过后再实施。本文描述的是拟改动，不代表功能已经上线。

## 一、这次要改成什么样

让每个使用者只需要理解自己的工作，不需要学习系统内部的归因引擎、绑定编号、批次、草稿和切换边界。

| 使用者 | 主要工作入口 | 日常要做的事 |
| --- | --- | --- |
| 管理员中的运营人员 | 运营管理 | 接入渠道、管理人员权限、管理任务和定价、审核和分发关键词、处理作品与业务异常 |
| 管理员中的财务人员 | 财务做账 | 上传知乎 Excel，核对自动计算结果，导出财务单，处理提现和付款登记 |
| 团长 | 团队业务、收入与提现 | 领取和分发关键词、管理团队、在授权范围内设置达人单价、审核作品、查看团队账目和申请提现 |
| 达人 | 我的关键词、收入与提现 | 获取关键词、提交作品、查看自己的收入、申请提现 |

管理员仍属于 admin 身份，运营和财务是不同岗位权限。不能只是换两个按钮、实际仍允许所有岗位修改全部数据。保留具有完整权限的管理员，用于管理岗位授权。

OPC 继续作为多平台聚合系统。账号、组织、权限和公共财务放在公共核心；知乎 Excel、邮件、渠道口径、关键词处理留在知乎模块。以后接入 API 型平台，也沿用相同的人员和资金流程。

## 二、现在为什么不好用

已核对当前三端页面和后台流程，主要存在以下问题：

1. 同一业务同时出现旧报表导入、结算批次、收益页面和新归因与对账，用户不知道应该走哪个入口。
2. 业务菜单混有大量历史、辅助和系统功能，财务和达人都要从长菜单里寻找日常工作。
3. 上传报表后，还需要人为选择报告类型、确认导入、生成应付草稿和切换试算状态；这些内部步骤暴露得过多。
4. “绑定编号”“来源修订”“报价版本”“原始计算快照”等内部信息直接出现在操作区。
5. 关键词使用和作品提交分散，用户还要手工找编号关联作品。
6. 管理员的运营、财务岗位没有完整独立的权限控制；目前主要依据 admin、leader、creator 三种身份授权。
7. 新对账结果和旧收益、提现数据未形成统一资金账。现有“已确认”仅表示对账完成，不能当作已打款或可提现。

因此，本次改造既要重新组织前端，也要补充必要的后台自动衔接。只隐藏页面或修改文案，解决不了流程问题。

## 三、每个角色具体怎么用

### 1. 财务：围绕一张财务账单操作

默认进入“财务做账”，主要页面内容如下：

- 顶部只有一个主要动作：**上传知乎报表**。
- 上传后显示：报表日期、订单数、本期应付合计、需要处理的问题数。
- 下方按收款人汇总：姓名、身份、订单量、金额、处理状态。
- 点击某个人，才展开关键词、订单和单价等明细。
- 正常操作按钮为：**核对并确认账单、导出财务单**。
- 提现申请和付款记录在同一财务入口下处理，不再去其他结算页面重复登记。

正常流程：

> 上传报表 → 自动算出人员和金额 → 财务核对并确认 → 导出做账或按提现申请办理付款。

系统自动完成文件类型识别、日期读取、去重、归属匹配、按生效报价计费、生成各方账单和更新收入展示。不再要求财务操作“创建批次”“生成草稿”“切换引擎”。

**仍然需要人工判断的事情必须保留：**

- 报表更正导致金额变化，需要明确核对。
- 关键词归属不明、缺单价、作品未通过等，只提示具体原因和负责岗位。
- 付款和“已付款”登记不能因为上传文件而自动完成。

财务人员默认只读定价规则；修改规则应回到运营流程，并按授权审核。

### 2. 运营：围绕人员、渠道和关键词管理

运营入口内按工作事项组织：

| 页面 | 主要内容 |
| --- | --- |
| 渠道与任务 | 查看接入状态、设置报表渠道名称、管理推广任务 |
| 人员与权限 | 管理团长、团队达人、独立达人，分配项目和岗位权限 |
| 关键词管理 | 创建或审核关键词，查看归属，分发给团长或独立达人 |
| 定价规则 | 设置任务单价、适用人员和生效日期；必要时提交财务审核 |
| 审核与待办 | 审核作品，处理未匹配渠道、未分配关键词、缺报价和争议 |

“渠道映射”改为用户能理解的“报表中的渠道名称”；复杂别名、历史兼容等选项放进“更多设置”。单一渠道或任务可以自动选中，存在歧义时才让用户选择。

独立达人可以直接获得授权关键词；团队达人由所属团长分发。领取优先期、关键词不可重复占用等规则由后台执行，页面只显示“可以领取”“暂时不可领取”及必要原因。

创建、修改、停用、归属调整仍要留下操作记录。技术日志放到管理员的维护入口，不出现在日常业务表格中。

### 3. 团长：管团队，看收入，申请提现

主要入口只有两个：

- **团队业务**：关键词领取与分发、团队成员、团队单价、作品审核。
- **收入与提现**：团队业绩、本人收益、达人应得金额、可提现金额、提现进度。

分发关键词时选择成员姓名，不填写用户或绑定编号。正常报价已经生效、作品已经审核的业务，不要求团长每次报表上传后再逐条重复确认。

对改价、来源更正、归属争议等影响金额的事项，再显示明确的待办。团长只能查看和管理授权范围内的团队，独立达人不进入其团队账。

### 4. 达人：用关键词和提现

“我的关键词”只显示本人被分配的关键词，以及本人有资格领取的关键词。

主要动作：

> 领取或接收关键词 → 点击“提交作品”，填写链接 → 查看审核结果和收入 → 申请提现。

“开始使用”、作品与关键词关联等内部记录，在提交作品时自动衔接。作品被退回时，直接显示修改原因和重新提交入口。

达人不显示渠道设置、定价管理、报表导入、归因处理、草稿生成和系统维护。只显示自己适用的单价、自己的收入和提现记录。

## 四、资金口径：必须先统一，再开放提现

### 推荐方案：平台统一办理派发

平台根据统一资金账，向达人和团长分别支付各自最终应得的部分。团长页面可以展示团队业务总额，但可提现金额只计入团长自己的净收益，避免重复付款。

沿用当前联测数据：

| 最终收款人 | 应得金额 |
| --- | ---: |
| 团队达人 A | 390 元 |
| 团队达人 B | 240 元 |
| 独立达人 | 140 元 |
| 团长 | 195 元 |
| 平台合计应付 | 965 元 |

团长业务应收 825 元，其中 630 元属于团队达人，团长留存 195 元。**若采用平台统一派发，825 元不能全部进入团长可提现余额，再让达人另外提现 630 元。**

如果实际业务是“平台先付团长，由团长自行给达人打款”，就必须采用另一套资金流：平台向团长支付 825 元、向独立达人支付 140 元；团队达人向团长申请领取其 630 元，不能再向平台重复申请同一笔款。两种模式不能混用。

### 收入与提现分开显示

统一使用以下含义：

| 状态或金额 | 含义 |
| --- | --- |
| 待确认收入 | 系统已计算，尚有审核或财务核对未完成 |
| 已确认收入 | 账单已经确认，尚不代表收到款项 |
| 可提现金额 | 按选定派发模式和资金可用规则，扣除冻结、已申请与已支付后的金额 |
| 提现处理中 | 申请占用对应余额，等待审核或付款 |
| 已付款 | 实际完成付款并登记凭证，不能用“审批通过”代替 |

是否要求上游款项到账后才释放可提现余额，应作为明确业务规则配置。默认建议确认账单和资金可用均满足后再开放申请。

第一阶段付款采用**财务线下打款＋在系统登记凭证**，不宣称已连接银行自动转账。财务单应包含收款人、来源账单、金额、必要收款资料和付款状态，并限制敏感信息的可见权限。

对重复申请、多人并发审核、付款回执重复提交，都要避免重复占用或重复付款；报表更正也必须保留原账和差额，不能覆盖已支付记录。

## 五、要自动化什么，要隐藏什么

| 当前方式 | 拟调整 |
| --- | --- |
| 财务选择报告类型，再预览、确认导入 | 上传后自动识别并分析；异常给出可执行提示 |
| 手工填写账期、生成每一层应付草稿 | 默认使用报表日期，自动生成各方账单；日期筛选仍可使用 |
| 日常人员操作试算、切换边界 | 转为后台规则和运营维护设置，保留旧账隔离校验 |
| 每次都先让团长逐条确认，再让财务确认 | 推荐改为预先生效的定价与作品审核作为依据，正常账单由财务统一核对；特殊变动单独处理 |
| 达人输入绑定编号登记作品 | 从关键词直接提交，系统建立关联 |
| 金额表中显示各种数据库编号、状态码 | 显示人员姓名、金额及“待审核作品”等业务状态 |
| 新收入与旧收益页面互不对应 | 日常入口统一，明确区分历史账与新账，按来源防止重复计入 |
| 旧入口和新入口同时作为日常功能 | 新入口承接日常工作；历史资料保留查询，旧链接提供明确导向 |
| 技术明细铺满页面 | 用户点击“查看明细”时才展开业务明细；技术诊断仅在维护工具中查看 |

文件损坏、表头不支持等格式问题，应在入账前说明位置和修改办法。业务归属、定价或风险问题应保留待办，不静默丢弃、不默认分给某人，也不按零元掩盖。

## 六、实施步骤与影响范围

### 第一步：确定页面和业务规则

先审核本文，确认岗位分工、正常账单确认方式和资金派发模式。随后制作四类使用者的关键页面预览，再按审核意见实施。

### 第二步：整理入口并落实岗位权限

- 合并三端日常业务菜单，调整登录后的工作入口。
- 拆分运营、财务工作页面，收起历史和维护工具。
- 将岗位授权、项目成员范围落实到后台接口；直接请求接口也不能越权。
- 保留完整管理员权限，迁移现有账号时不擅自改变人员归属。

### 第三步：接通上传、自动计算和收入展示

- 财务上传后自动归属、计算并生成可核对账单。
- 收入页面读取统一的业务结果，避免同一条数据重复进入新旧账。
- 将作品提交和关键词使用整合；按已审核规则简化正常账单确认。
- 支持重复上传、异步处理中断恢复、报表更正和异常重算。

### 第四步：接通提现与付款登记

- 根据审核确定的派发模式建立公共资金账与账单来源关联。
- 接通可提现余额、申请、审核、占用释放、付款登记及凭证。
- 将财务状态真实反馈给团长与达人。
- 自动银行转账另行接入；本计划不以修改页面状态冒充实际付款。

### 第五步：联测验收后切换日常入口

- 先在现有本地测试环境演示，再由你按角色手工验证。
- 保留原始报表、历史账和审计记录，按明确日期与来源区分新旧流程。
- 旧记录未完成核对前，不自动迁入新资金账。
- 本次实施不包含自动提交或推送仓库；提交、推送仍等你明确要求。

涉及范围：三端业务入口及公共页面、共享业务视图、OPC 岗位权限与公共资金能力、知乎报表和账单接口。不是只改前端，也不会把知乎专属处理写进 OPC 公共骨架。

## 七、怎么判断改造真的有用

### 使用难度验收

- 财务在正常资料齐全时，通过“上传—核对确认—导出或办理付款”完成工作，不需要知道归因引擎或批次是什么。
- 达人从关键词直接提交作品，不需要复制任何内部编号。
- 团长能一眼区分团队业绩、本人收益和可提现金额。
- 每个页面有清晰主要动作；无数据时说明下一步；错误提示能说明怎么处理。
- 同一模块在三端保持一致的布局宽度、表格和按钮规则。
- 新用户能在不阅读技术文档的情况下完成其角色的主要操作。

### 正确性验收

- 现有模拟报表 5 行、65 单，按当前报价计算平台应付 965 元。
- A 为 390 元，B 为 240 元，独立达人为 140 元，团长净收益为 195 元；零订单记录不产生收益。
- 同一文件重复上传不重复计账；上传更正文件保留差额与核对记录。
- 缺价、未知关键词、未审核作品、来源风险均能给出明确待办。
- 财务不能修改运营授权，运营不能登记付款；团长和达人不能查看或操作不属于自己的数据。
- 达人、团长提现时，不能重复占用同一笔资金；驳回按规则释放余额；付款登记须有真实依据。
- 在提现服务未完成接入之前，不显示虚假的可提现金额或“已付款”。

## 八、本次请重点审核的三项选择

| 审核项 | 推荐采用 | 需要你确认的业务边界 |
| --- | --- | --- |
| 资金派发 | 平台分别向达人、团长派发最终应得款，团长只提现净收益 | 是否实际上必须先付团长、由团长另行向团队达人付款 |
| 正常账单确认 | 生效定价＋作品审核完成后，由财务统一核对，取消每次报表都逐条等待团长确认 | 是否有必须由团长再次签认每期账单的业务要求 |
| 付款方式 | 先支持提现审核、线下付款、凭证登记；再接银行自动转账 | 是否接受先以线下付款形成完整闭环 |

其余页面组织和交互方式按本文执行。审核期间暂停功能实现；审核通过后再实施、部署和联测。
