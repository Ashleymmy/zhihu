## 📋 一、背景与问题

### 当前困境

经与知乎官方确认，系统当前基于的技术假设**已失效**：

| 原假设 | 实际情况 | 影响 |
|-------|---------|------|
| ✅ 可通过 API 查询审核状态 | ❌ API 不可用 | 审核状态同步功能失效 |
| ✅ 可通过 API 拉取收益数据 | ❌ API 不可用 | 数据拉取任务失效 |
| ✅ 知乎提供达人级细粒度数据 | ❌ 仅提供关键词汇总 | 无法直接分配收益 |
| ✅ 作品审核状态可追踪 | ❌ 无相关接口 | 作品状态管理失效 |

### 核心问题

**数据链断裂**：知乎官方通过**邮件**发送汇总数据 → 我们需要将其拆分到具体达人

```
知乎官方数据（邮件）：
┌────────────────────────────────────┐
│ 关键词: 知乎推广工具                │
│ 搜索量: 1000                       │
│ 转化数: 50                         │
│ 收益:   5000 元                    │
└────────────────────────────────────┘
                ❓
        如何分配给达人？
                ↓
┌─────────────────────────────────────┐
│ 达人 A: 2500 元 (5 个作品)          │
│ 达人 B: 1500 元 (3 个作品)          │
│ 达人 C: 1000 元 (2 个作品)          │
└─────────────────────────────────────┘
```

---

## 🎯 二、解决方案概览

### 核心思路

**建立"关键词 → 作品 → 达人"的归因链**

```
┌─────────────────────────────────────────────┐
│            归因链设计                        │
└─────────────────────────────────────────────┘

1️⃣ 达人绑定关键词
   达人声明："我要使用'知乎推广工具'这个关键词"
   
2️⃣ 达人登记作品
   达人记录："我用'知乎推广工具'发布了一个作品"
   - 作品链接：https://douyin.com/xxx
   - 浏览量：10000
   - 点赞数：500
   
3️⃣ 知乎数据到达（邮件）
   知乎发送："关键词'知乎推广工具'产生了 5000 元收益"
   
4️⃣ 归因引擎计算
   系统计算：根据作品数量和质量，分配收益
   
5️⃣ 管理员审核
   管理员确认：检查分配是否合理
   
6️⃣ 生成收益记录
   达人查看：在系统内看到自己的收益
```

### 系统改造范围

| 模块 | 改造类型 | 工作量 |
|-----|---------|--------|
| **废弃功能** | 标记 Deprecated | 1 天 |

| **作品登记系统** | 新增 | 3 天 |
| **邮件数据导入** | 新增 | 4 天 |
| **归因引擎** | 新增 | 5 天 |
| **前端界面** | 新增 | 5 天 |
| **测试与上线** | 集成测试 | 5 天 |
| **合计** | - | **26 人天（约 6 周）** |

## 💡 三、核心功能

### 功能 1：关键词绑定

**用户**：达人、团长

**场景**：达人在发布作品前，先在系统内绑定要使用的关键词

**价值**：
- ✅ 明确关键词使用权
- ✅ 避免归因冲突
- ✅ 支持团长独占模式

---

### 功能 2：作品登记

**用户**：达人

**场景**：达人发布作品后，在系统内登记作品信息和质量数据

**价值**：
- ✅ 建立"作品 → 关键词"关联
- ✅ 采集质量数据（浏览量、点赞数）
- ✅ 为归因提供计算依据

---

### 功能 3：邮件数据导入

**用户**：管理员

**场景**：每天收到知乎邮件后，上传附件到系统

**价值**：
- ✅ 自动解析 CSV/Excel 数据
- ✅ 数据验证和去重
- ✅ 自动触发归因任务

---

### 功能 4：智能归因引擎

**用户**：系统自动运行

**场景**：数据导入后，自动将关键词收益拆分到达人

**核心算法**：
```
达人收益 = (达人作品质量总分 / 所有作品质量总分) × 关键词总收益

质量分 = 浏览量 × 0.5 + 点赞数 × 2 + 转发数 × 5 + 评论数 × 3
```

**价值**：
- ✅ 自动化分配，减少人工
- ✅ 公平合理（质量优先）
- ✅ 置信度评估（低置信度需要人工审核）

---

### 功能 5：归因审核工作台

**用户**：管理员

**场景**：审核系统自动归因的结果，调整异常数据

**价值**：
- ✅ 人工兜底，避免错误分配
- ✅ 处理异常情况
- ✅ 争议仲裁

## 📊 四、投入产出分析

### 开发投入

| 资源 | 数量 | 时间 | 说明 |
|-----|-----|------|------|
| **后端开发** | 1 人 | 3 周 | 核心算法 + 5 个新模块 |
| **前端开发** | 1 人 | 2 周 | 4 个新页面 |
| **测试工程师** | 1 人 | 1 周 | 集成测试 + 验收测试 |
| **产品经理** | 0.5 人 | 贯穿 | 需求确认 + 用户培训 |
| **合计** | 约 2.5 人 | 6 周 | - |

### 效益预估

| 维度 | 改造前 | 改造后 | 提升 |
|-----|-------|-------|------|
| **数据处理效率** | 人工 Excel 计算（2-4 小时/天） | 自动归因（5-10 分钟） | 节省 90% 时间 |
| **分配准确性** | 人工分配，易出错 | 算法分配 + 人工审核 | 准确率 >95% |
| **可扩展性** | 达人增加后人工处理崩溃 | 自动化处理，可支持 1000+ 达人 | 10 倍扩展能力 |
| **透明度** | 达人不清楚收益来源 | 达人可查看作品贡献度 | 满意度提升 30% |
| **争议率** | 约 20%（估计） | <5% | 降低 75% |

### ROI 计算

**假设**：
- 当前每天人工处理 2 小时，人力成本 500 元/小时
- 改造后节省 1.8 小时/天
- 一年工作日 250 天

**年节省成本**：
```
1.8 小时/天 × 500 元/小时 × 250 天 = 225,000 元/年
```

**开发成本**（一次性）：
```
2.5 人 × 6 周 × 40 小时/周 × 500 元/小时 = 300,000 元
```

**投资回收期**：
```
300,000 / 225,000 = 1.33 年（约 16 个月）
```

**3 年 ROI**：
```
(225,000 × 3 - 300,000) / 300,000 = 125%
```

## ✅ 六、关键决策点

在开始开发前，**必须**确认以下问题（详见《关键问题与决策清单》）：

### 必须立即确认（Week 0）

1. ✅ **邮件数据格式**
   - 提供 3 份真实样本（脱敏版）
   - 确认字段名称和数据类型

2. ✅ **关键词使用规则**
   - 团长是否可以独占关键词？
   - 散户达人如何管理？

3. ✅ **归因算法选择**
   - 按作品数量平均分？
   - 按作品质量加权分？（推荐）
   - 人工分配？

4. ✅ **团长抽成规则**
   - 是否抽成？抽成比例多少？

5. ✅ **作品登记要求**
   - 是否强制登记？
   - 质量数据如何采集？

### 可以在开发中调整（Week 1-4）

- 质量分数计算公式的权重
- 置信度阈值
- 时间窗口设置
- 界面交互细节

**附录：关键术语**

| 术语 | 解释 |
|-----|------|
