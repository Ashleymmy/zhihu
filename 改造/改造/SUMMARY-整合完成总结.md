## 🎯 核心设计思想

### 双层架构

```
┌─────────────────────────────────────────────────┐
│  第 1 层：归因引擎（新增）                         │
│  职责：关键词收益 → 达人归因收益                   │
│  输入：邮件数据（关键词汇总）                       │
│  输出：每个达人的"归因收益"                        │
└─────────────────────────────────────────────────┘
               ↓ 映射为
┌─────────────────────────────────────────────────┐
│  第 2 层：定价规则（现有 pricing_rules）           │
│  职责：归因收益 → 最终入账                         │
│  输入：达人的"归因收益"（= source_amount）         │
│  输出：达人应得 + 团长抽成                         │
└─────────────────────────────────────────────────┘
```

### 关键优势

1. **复用现有体系**
   - ✅ 无需重构定价逻辑
   - ✅ 统一的定价规则管理
   - ✅ 完整的审计链路

2. **灵活的业务规则**
   - ✅ 支持多种定价方式（fixed / percentage）
   - ✅ 支持按用户定制规则
   - ✅ 全流程自动化

3. **可追溯性**
   - ✅ 每笔收益可追溯到关键词
   - ✅ 每笔收益可追溯到作品
   - ✅ 每笔收益可追溯到应用的定价规则

## 📊 示例场景

### 输入

**邮件数据**：关键词收益 5000 元

**作品数据**：
- 达人 A: 5 个作品，质量分 2500
- 达人 B: 3 个作品，质量分 1500
- 达人 C: 2 个作品，质量分 1000

**定价规则**：
- 达人规则: 60% percentage
- 团长规则: 10% percentage

### 计算过程

**第 1 层：归因引擎**
```
达人 A 归因收益 = 5000 × (2500/5000) = 2500 元
达人 B 归因收益 = 5000 × (1500/5000) = 1500 元
达人 C 归因收益 = 5000 × (1000/5000) = 1000 元
```

**第 2 层：定价规则**
```
达人 A: 2500 × 0.6 = 1500 元 → 团长抽 150 元 → 最终 1350 元
达人 B: 1500 × 0.6 = 900 元  → 团长抽 90 元  → 最终 810 元
达人 C: 1000 × 0.6 = 600 元  → 无团长      → 最终 600 元
团长 X: 150 + 90 = 240 元
```

### 结果

| 用户 | 归因收益 | 应得 | 抽成 | 最终 |
|-----|---------|-----|------|------|
| 达人 A | 2500元 | 1500元 | -150元 | 1350元 |
| 达人 B | 1500元 | 900元 | -90元 | 810元 |
| 达人 C | 1000元 | 600元 | 0元 | 600元 |
| 团长 X | - | - | +240元 | 240元 |
| **合计** | **5000元** | **3000元** | - | **3000元** |

## 🔄 与原方案的变化

### 变化 1：定价逻辑

**原方案**：
```
归因引擎直接计算最终收益（包含团长抽成）
```

**新方案**：
```
归因引擎计算"归因收益" → 定价规则计算"最终入账"
```

### 变化 2：数据表

**原方案**：
- 新增 `attribution_results` 表，包含 `final_revenue` 字段

**新方案**：
- `attribution_results.allocated_revenue` = 归因收益
- 复用 `settlement_items.source_amount` = 归因收益（映射）
- 复用 `earnings.amount` = 最终入账

### 变化 3：团长抽成

**原方案**：
```
在归因引擎中计算团长抽成
```

**新方案**：
```
复用现有的 pricing_rules 中的团长规则
```

## ✅ 优势总结

### 技术优势

1. **复用现有代码**
   - 无需重写定价逻辑
   - 无需重写团长抽成逻辑
   - 无需新增定价相关的表

2. **统一管理**
   - 定价规则集中在 `pricing_rules` 表
   - 一处修改，全局生效

3. **可扩展性**
   - 未来可支持更复杂的定价规则
   - 归因算法和定价规则独立演进

### 业务优势

1. **灵活的定价**
   - 支持按用户定制（target_user_id）
   - 支持按角色统一（target_role）
   - 支持固定单价或百分比

2. **完整的审计**
   - `relay_logs` 记录每次定价规则应用
   - 可追溯每笔收益的计算过程

3. **自动化程度高**
   - 邮件导入 → 归因 → 定价 → 入账
   - 全流程自动化
