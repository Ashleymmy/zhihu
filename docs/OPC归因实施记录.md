## 当前实现与入口

三端入口：`/{admin|leader|creator}/modules/zhihu/keywords`，名称“归因与对账”。共用模块页面位于 `apps/module-views/zhihu`，通过 workspace 包声明依赖，确保修改页面会触发三端类型检查和构建。

| 区域 | 当前实现 |
|---|---|
| 关键词 | 创建、上游成功核实、失败重试、24 小时优先、领取、分配、使用、人工释放、停止新增 |
| 报价 | 项目＋账号＋任务＋付款关系；发布版本；未来调价；倒挂和缺价校验 |
| 报告 | `.xlsx` 预览、原文件与行留存、下载、确认、分段处理、异常重试、版本核实与重建 |
| 归因 | 唯一渠道映射、独占绑定、业务日期选价、当前结果指针、角色金额投影及来源详情 |
| 核验 | 登记作品、管理员或非本人作品的所属团长首次核验；本人核验交管理员；争议由管理员解除 |
| 对账 | 每条事实保留应付快照；按账期批量预览，选择本人付款草稿批量确认；任一项失败则整批回滚 |
| 恢复 | 原始行处理状态＋持久任务＋租约；提交后投递失败仍有待办，Worker 重启继续剩余行 |
| 切换 | 管理端“试算与切换”；账号、项目、起始日期唯一记录，日期不可移动，trial/enabled/stopped 可审计 |
| 旧数据 | 按页盘点旧词、共词数量及来源天数；不自动迁移历史绑定、不改旧 ID、不重算 earnings |

确认顺序：团队路径先由团长确认达人层，再由管理员确认团长层。直属达人、团长本人执行均只有一层代理应付。确认代表对账完成，界面不表示已经付款。

## 数据库与契约

使用现有模块迁移入口，增加 `018_exclusive_keywords.sql` 至 `024_revision_rebase.sql`。`015—017` 原文件未改。

| 迁移 | 主要结构 |
|---|---|
| 018 | `zh_agency_spaces`、`zh_channel_mappings`、`zh_keywords`、`zh_keyword_bindings`、`zh_idempotency_requests` |
| 019 | `zh_price_agreements`、`zh_price_versions` |
| 020 | `zh_import_batches`、`zh_import_rows`、`zh_metric_facts`、`zh_metric_revisions`、`zh_attribution_results`、`zh_exceptions` |
| 021 | `zh_evidence`、`zh_statement_entries`；事实增加当前结果指针 |
| 022 | `zh_processing_jobs`：账号、项目、批次、处理人、租约、尝试次数、错误及补投时间 |
| 023 | `zh_engine_routes` 与切换事务锁；用于新旧入口共同检查 |
| 024 | 修订候选代次及被替代候选引用；重建时保留原候选内容 |

旧设计中的对账头表和明细表，首期收敛为逐事实的 `zh_statement_entries`；账期只是批量操作的查询范围。每条记录仍独立保存付款关系、来源版本、报价版本、金额和前次确认引用，确认后不可覆盖。每次最多预览 500 条事实、确认 100 条，页面默认 25 条分页。

HTTP 响应遵循现有 `serialize`，统一输出 camelCase；数据库使用 snake_case。页面字段已按实际 HTTP 契约验证。金额字符串始终保留四位小数，用 BigInt 缩放计算；新查询显式将 DECIMAL 转为字符串，旧数据库池选项未改。

一个事实的唯一范围是账号＋稳定渠道映射＋关键词＋业务日期。综合报告拥有全部指标；订单报告拥有订单和可选收益，搜索报告拥有搜索量。不同报告的交叉指标不会相加。不同值产生待核实修订；过期候选可基于当前事实重建，再明确接受或驳回。订单来源未提供收益时，该版本收益为空，不继承旧订单版本的收益；搜索分报不改变订单或收益。

对账确认、来源接受和差额生成共用事实行锁。当前结果通过 `current_result_id` 确定，不依赖最大自增 ID。批量确认先按事实 ID 顺序锁定，拒绝其他付款主体、未核验、争议或过期草稿。

## 新旧边界与回退

1. 首次登记必须为 trial。选择未被旧来源或历史账处理的起始日期；该日及以后由新引擎处理，旧日期继续使用兼容入口。
2. 确认真实样本口径后，管理员可启用 enabled。此动作只开放模块对账确认，不开放公共资金操作。
3. 停止时切为 stopped。新引擎停止业务写入，事实、原文件、价格和对账历史保留；原边界继续拦截旧财务。
4. 恢复时沿用原日期及来源记录；不删除新表，不自动向旧 earnings 重放。旧版本如没有日期边界守卫，不可直接作为可写回退版本。
5. 旧 Excel 确认、手动结算审批、自动收益结算、旧 API 指标写入、无法证明来源范围的申诉调账均有边界检查。旧计划修改、删除和重试不能绕过新词库管理。

历史共词只做盘点和隔离，不推断谁产出了订单。进入新周期使用新关键词。已登记事实的关键词也不能按“未使用”释放。

## 恢复与运行

启用知乎模块时注册新处理器；调度器每 10 秒尝试补投到期任务。每次最多处理 200 行，租约 120 秒；失败记录保留并延迟重试。账号、项目或处理人停用时不会继续处理，可由有效管理员从报告页补投。

上游创建的 local 状态可补投；syncing 状态代表上游结果可能不确定，不能盲目重复创建，需核对上游状态。明确失败可从新词库入口重试，任务携带真实 accountId/projectId。没有新增多套真实凭据配置能力。

`ModuleDataProvider` 仅查询已接受来源的有效订单和搜索量，按调用者范围返回；无数据为 empty、缺失指标为 null。没有注册新的 FinanceProvider，也没有写钱包、提现或付款接口。
