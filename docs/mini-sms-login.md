> 2026-10-03 更新：小程序新版改为账号密码注册，手机号验证后置至个人信息。本文中的旧短信注册流程仅用于兼容旧客户端；以 [当前账号流程](mini-auth-flow.md) 为准。

# 小程序验证码登录

网站密码登录保持原有规则。小程序保留账号密码、微信登录，并在 `SMS_LOGIN_ENABLED=1` 时显示验证码登录。

## 账号规则

- 仅限已验证手机号、已绑定当前微信、启用且无需强制改密的现有账号。
- 首次绑定微信仍需网站账号密码。验证码登录不会新建账号、重绑微信、修改角色或归属。
- 旧账号先用密码登录，在“我的 → 个人信息 → 手机号验证”填写当前密码并接收验证码。已有手机号只能验证原号码；未登记号码可以补充。改号需管理员处理，现有管理接口改号会清除验证状态。
- 短信注册完成的账号已验证手机号，不必重复验证。
- 只替换小程序会话，保留 Web 和移动浏览器会话；开发者仍不受数量限制。

## 接口与保护

所有接口通过现有签名云中继 `/api/v1/mini/bridge`，信任云端微信身份，不接受客户端伪造身份。

| 云中继路径 | 用途 |
| --- | --- |
| `GET /core/auth/sms-policy` | 查询是否开放短信登录 |
| `POST /core/auth/login-code` | 向当前绑定账号的已验证手机号发送验证码 |
| `POST /core/auth/sms-login` | 手机号与验证码登录现有账号 |
| `POST /core/auth/phone-code` | 已登录账号用当前密码申请手机号验证短信 |
| `POST /core/auth/verify-phone` | 已登录账号用当前密码及验证码完成验证 |

验证码六位、五分钟有效、六十秒后可重发、最多五次错误。注册、登录、手机号验证用途隔离，共享手机号、微信身份和全局发送额度。数据库只存验证码摘要；密码、手机号、绑定关系或账号状态变化会阻止旧凭证登录。验证消费与会话创建在同一事务提交，重复或并发提交仅成功一次。

迁移 `010_sms_login.sql` 增加用途、账号状态摘要和已验证手机号唯一约束。部署前检查重复已验证手机号。此迁移兼容上一版注册后端，不改变已发注册验证码的摘要格式。

## 发布与人工验收

1. 备份生产数据库和短信配置，执行迁移，再部署后端；`SMS_LOGIN_ENABLED=1` 开放登录及手机号验证。注册试收邀请范围由原独立开关控制，不随登录开关扩大。
2. 继续使用现有 ECS RAM 临时凭据、短信签名和模板，不在小程序内放密钥。试收期所有用途合计每天最多十次发送尝试。
3. 上传小程序并设为体验版。旧体验包不会自动增加新按钮。
4. 本人主动试收：新账号注册后退出，选择验证码登录，检查账号、归属及项目不变；旧账号先验证手机号再退出登录。
5. 错误验证码、重复验证码、另一微信、未验证号码、停用账号应被拒绝；成功后网站原会话仍可用。首次绑定继续使用密码。

回滚时恢复上一应用镜像和短信配置，保留新增数据库列与索引。不得恢复整库覆盖上线后新增业务数据。
