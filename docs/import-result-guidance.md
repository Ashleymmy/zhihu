# 报表导入后的处理结果

历史邮件 / Excel 导入页将文件保存与业务处理分开展示。`confirmed` 仅表示文件已保存，不代表归因、收益或付款完成。

- 打开页面会读取最近已保存批次的处理结果；刷新和查看历史批次均为只读操作。
- 尚未开始或存在未处理行时，有导入权限且职责为全量的管理员、开发者可点击“继续归因”。该操作复用原文件与归因批次，并保留确认步骤。
- 归因有待办时，页面显示具体原因并链接到“数据待办”。归因完成后引导核对账单，跳转携带项目、账号及报表业务日期。
- 没有收入金额列的订单报表仅显示订单数、搜索量，收入由业务归属及单价计算，不能把订单数视为金额。
- 历史旧任务、多项目记录和结果不可读分别展示，不能据文件保存状态推断收益完成。

修复：旧导入项目查找只把字面角色 `admin` 视为平台管理角色，导致没有项目成员记录的 `developer` 在文件保存后无法继续归因。现使用统一 staff 判断，并在确认保存前解析及校验项目权限；接口原有权限和职责限制保持生效。

验证：后端导入与进度测试 42 项、前端单元测试 48 项；使用真实前端与隔离 API 数据验证刷新恢复、显式继续操作、待办和账单日期跳转及 390px 移动布局。上线核验只读取生产记录，不自动重新确认历史批次或生成财务数据。
