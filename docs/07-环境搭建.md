## 三、安装 Node.js

### 版本要求

**必须 ≥ 20.19.0**。Vite 6 要求 Node 20.19+ 或 22.12+。

### 方案 A：官网直装（简单，适合只做这一个项目）

1. 打开 [nodejs.org](https://nodejs.org)
2. 下载 **LTS** 版本（当前是 22.x）
3. 一路下一步安装
4. 打开新的终端验证：

```bash
node -v    # 应显示 v22.x.x 或 v20.19+
npm -v     # 应显示 10.x.x
```

### 方案 B：用版本管理工具（推荐，适合同时做多个项目）

**Windows** — 用 [nvm-windows](https://github.com/coreybutler/nvm-windows/releases)：

```powershell
nvm install 22.12.0
nvm use 22.12.0
node -v
```

**macOS / Linux** — 用 [nvm](https://github.com/nvm-sh/nvm)：

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# 重开终端后
nvm install 22
nvm use 22
node -v
```

### 配置国内镜像（可选，国内网络建议配）

```bash
npm config set registry https://registry.npmmirror.com

# 验证
npm config get registry
```

想换回官方源：

```bash
npm config set registry https://registry.npmjs.org
```

## 四、初始化项目

### 4.1 创建 Vite 项目

`web/` 目录目前只有官方 PDF，我们在这里初始化项目。

```bash
cd D:\ITEM\zhihu-app\web

# 在当前目录初始化（注意那个点，表示当前目录）
npm create vite@latest . -- --template vue-ts
```

如果提示目录非空，选择 **`Ignore files and continue`**（保留 PDF 文件）。

### 4.2 安装依赖

```bash
# 基础依赖
npm install

# 运行时依赖（版本锁定，见 README 的技术栈说明）
npm install axios@1.7.9 \
            crypto-js@4.2.0 \
            pinia@2.3.0 \
            vue-router@4.5.0 \
            element-plus@2.9.1

# 开发依赖
npm install -D @types/crypto-js@4.2.2 \
               vitest@2.1.8 \
               @vitest/coverage-v8@2.1.8 \
               @vue/test-utils@2.4.6 \
               happy-dom@15.11.7 \
               msw@2.6.8 \
               eslint@9.17.0 \
               @eslint/js@9.17.0 \
               typescript-eslint@8.18.2 \
               eslint-plugin-vue@9.32.0 \
               eslint-config-prettier@9.1.0 \
               prettier@3.4.2 \
               vue-tsc@2.1.10 \
               @types/node@22.10.2
```

> **为什么锁定精确版本？**
> 用 `^` 会让不同人装到不同的小版本，出现「我这能跑你那不能跑」的问题。
> 锁定版本后大家环境一致，升级依赖变成一个显式的、可 Review 的动作。

按 01 文档的六层架构建目录：

### 4.4 配置 `vite.config.ts`

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { fileURLToPath, URL } from 'node:url'

export default defineConfig({
  plugins: [vue()],

  resolve: {
    alias: {
      // 让 @/xxx 指向 src/xxx，避免 ../../../ 这种相对路径
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },

  server: {
    port: 5173,
    open: true,

    /**
     * 开发代理：解决 CORS 问题。
     *
     * 浏览器直连 open.zhihu.com 会被同源策略拦住，
     * 所以让 Vite dev server 转发：浏览器请求 /api/xxx，
     * Vite 转成 https://open.zhihu.com/xxx。
     *
     * ⚠️ 这只是开发期方案。生产环境必须走自建 BFF，
     * 详见 docs/01-架构设计.md 的「安全边界」章节。
     */
    proxy: {
      '/api': {
        target: 'https://open.zhihu.com',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ''),

        // 打印代理日志，方便排查请求到底发去了哪
        configure: (proxy) => {
          proxy.on('proxyReq', (proxyReq) => {
            console.log(`[proxy] → ${proxyReq.method} ${proxyReq.path}`)
          })
          proxy.on('error', (err) => {
            console.error('[proxy] 错误：', err.message)
          })
        },
      },
    },
  },

  build: {
    sourcemap: false,   // 生产不出 sourcemap，避免暴露源码结构
  },
})
```

### 4.5 配置 `tsconfig.json`

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "types": ["vite/client", "vitest/globals"],

    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "noUncheckedIndexedAccess": true,

    "jsx": "preserve",
    "isolatedModules": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "resolveJsonModule": true,
    "noEmit": true,

    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  },
  "include": ["src/**/*.ts", "src/**/*.vue", "vite.config.ts", "vitest.config.ts"],
  "exclude": ["node_modules", "dist"]
}
```

> `noUncheckedIndexedAccess: true` 会让 `obj[key]` 的类型带上 `undefined`，
> 强制你做空值检查。刚开始会觉得烦，但能挡住很多运行时错误。

## 五、配置环境变量

### 5.1 创建 `.env.example`（提交 Git）

这是给团队看的模板，**不填真实值**：

```bash
# ==========================================================
# 环境变量模板
#
# 用法：复制本文件为 .env.local，在 .env.local 中填真实值
#      cp .env.example .env.local
#
# ⚠️ 本文件会提交到 Git，绝对不要在这里填真实凭证
# ==========================================================

# ---------- API 地址 ----------
# 开发环境：留空，走 vite.config.ts 里配的 /api 代理
# 生产环境：填自建 BFF 地址，如 https://bff.internal.example.com
VITE_API_BASE_URL=

# ---------- 签名模式 ----------
# true  = 浏览器本地计算签名（仅限本地开发）
# false = 由后端 BFF 计算签名（生产环境必须为 false）
VITE_ENABLE_LOCAL_SIGN=true

# ---------- 开发者凭证 ----------
# 开发者 Token。这个值本来就会随请求发出，敏感级别中等
VITE_DEV_ACCESS_TOKEN=

# ⚠️⚠️⚠️ 签名私钥 ⚠️⚠️⚠️
# 只允许写在 .env.local，且 .env.local 必须在 .gitignore 中
# 泄露后果：他人可伪造我方身份调用接口、刷爆日配额
# 生产环境此项必须为空，签名由 BFF 完成
VITE_DEV_SECRET_KEY=
```

### 5.2 创建 `.env.local`（不提交）

```bash
cd D:\ITEM\zhihu-app\web
cp .env.example .env.local
```

编辑 `.env.local`，填入运营给你的**测试**凭证：

```bash
VITE_API_BASE_URL=
VITE_ENABLE_LOCAL_SIGN=true
VITE_DEV_ACCESS_TOKEN=你的测试access_token
VITE_DEV_SECRET_KEY=你的测试secret_key
```

### 5.3 确认 `.gitignore`（🔴 关键步骤）

打开 `.gitignore`，确认包含这几行。**如果没有，立刻加上**：

```
# 依赖与产物
node_modules/
dist/
coverage/

# 环境变量 ★★★ 绝对不能漏
.env.local
.env.*.local

# 编辑器
.DS_Store
.idea/
*.swp

# 日志
*.log
npm-debug.log*
```

**立即验证**：

```bash
# 这条命令应该输出 .env.local 被忽略的信息
git check-ignore -v .env.local

# 期望输出类似：
# .gitignore:8:.env.local    .env.local
```

如果没有任何输出，说明 `.gitignore` 配错了，**不要继续，先修好**。

```bash
# 再确认一次它不在待提交列表里
git status --short | grep env
# 应该没有输出
```

## 七、常见问题

### 环境类

**Q1：`npm create vite` 报 `Unsupported engine`**

Node 版本太低。Vite 6 需要 ≥ 20.19。

```bash
node -v          # 看当前版本
nvm install 22   # 装新版
nvm use 22
```

---

**Q2：`npm install` 卡住不动或超时**

网络问题，换国内镜像：

```bash
npm config set registry https://registry.npmmirror.com
rm -rf node_modules package-lock.json
npm install
```

---

**Q3：`Cannot find module '@/utils/signature'`**

路径别名没配好。检查两个地方**都要配**：

1. `vite.config.ts` 的 `resolve.alias`（运行时解析）
2. `tsconfig.json` 的 `compilerOptions.paths`（类型检查）

改完重启 dev server 和编辑器的 TS 服务
（VS Code：`Ctrl/Cmd + Shift + P` → `TypeScript: Restart TS Server`）。

---

**Q4：VS Code 里 `.vue` 文件全是红波浪线，但 `npm run dev` 正常**

装 Vue 官方插件：搜索 **Vue - Official**（原 Volar）并启用。
同时确保**禁用**旧的 Vetur 插件（两者冲突）。

---

**Q5：`import.meta.env.VITE_XXX` 是 `undefined`**

三种可能：

1. 变量名没有 `VITE_` 前缀 → Vite 只暴露带此前缀的变量
2. 改了 `.env.local` 但没重启 dev server → 环境变量在启动时读取，**必须重启**
3. 文件名拼错 → 确认是 `.env.local` 不是 `env.local` 或 `.env.local.txt`

---

### 请求类

**Q6：控制台报 CORS 错误**

```
Access to XMLHttpRequest at 'https://open.zhihu.com/...' has been blocked by CORS policy
```

说明请求绕过了代理，直连了知乎。检查：

1. `vite.config.ts` 的 proxy 配置存在且正确
2. `.env.local` 里 `VITE_API_BASE_URL` 是**空的**（留空才会走 `/api` 代理）
3. `infra/http/client.ts` 的 `baseURL` 兜底值是 `'/api'`
4. 改完**重启** dev server

验证代理是否生效：终端应打印 `[proxy] → POST /alliance/api/...`。

---

**Q7：请求 404，但接口路径看起来是对的**

代理的 `rewrite` 规则问题。确认：

```typescript
rewrite: (path) => path.replace(/^\/api/, '')
```

请求 `/api/alliance/api/popularize_plan` 会被转发到
`https://open.zhihu.com/alliance/api/popularize_plan`。

注意路径里有两个 `api`：第一个是代理前缀，第二个是知乎接口路径的一部分。
不要在服务层的路径常量里漏掉 `/alliance/api`。

---

**Q8：接口返回 `timestamp 无效`**

这是最常见的报错，有三个可能原因：

1. **时间戳用了毫秒级** → 必须 `Math.floor(Date.now() / 1000)`
2. **本机系统时间不准** → 和 [time.is](https://time.is) 对比，误差应 < 1 分钟
3. **其实是签名错了** → 知乎在签名错误时也可能返回这个消息

按 [04 文档 § 七、排错手册](./04-签名机制.md#七排错手册) 逐步排查。
先跑 `npm run test:sign` 确认算法本身没问题。

---

**Q9：签名黄金用例失败**

对照 04 文档排错手册第三步的 8 项检查表。最高频的三个：

| 症状 | 原因 |
| --- | --- |
| kv 字符串里出现 `%` | 用了 `encodeURIComponent` 或 `URLSearchParams` |
| MD5 有大写字母 | 漏了 `.toLowerCase()` |
| 签名长度对但值不对 | `HmacSHA256` 参数顺序反了 |

用 `buildSignatureWithTrace()` 打印中间值，和 04 文档的黄金用例逐步对比。

---

**Q10：批量任务结果下载下来是损坏的文件**

没设 `responseType: 'blob'`。Axios 默认会把响应当 JSON 解析，
二进制数据会被破坏。

```typescript
// ✅ 正确
const response = await http.get(url, { responseType: 'blob' })
```

同时确认响应拦截器对 blob 类型做了跳过处理（见 03 文档 § 6.1）。

---

### 测试类

**Q11：测试报错 `Cannot find module 'msw/node'`**

MSW 2.x 的导入路径变了。确认版本 ≥ 2.0：

```bash
npm ls msw
```

导入写法：

```typescript
import { setupServer } from 'msw/node'   // Node 环境
import { http, HttpResponse } from 'msw' // handler 定义
```

---

**Q12：测试报 `Error: Cannot find module 'happy-dom'`**

装上并在 `vitest.config.ts` 里指定：

```bash
npm i -D happy-dom
```

```typescript
test: { environment: 'happy-dom' }
```

---

**Q13：测试报「请求未被拦截」错误**

这是**预期的保护机制**。`src/test/setup.ts` 里配了
`onUnhandledRequest: 'error'`，任何没被 mock 的请求都会让测试失败，
防止测试意外打真实接口消耗配额。

解决办法是**给这个请求写 MSW handler**，
而不是把配置改成 `'bypass'`。

---

### Git 类

**Q14：不小心提交了 `.env.local`**

🔴 **这是安全事故，立刻处理：**

```bash
# 1. 从 Git 追踪中移除（保留本地文件）
git rm --cached .env.local

# 2. 确认 .gitignore 里有 .env.local
echo ".env.local" >> .gitignore

# 3. 提交这次移除
git commit -m "chore: 移除误提交的 .env.local"
```

**如果已经 push 到远端**，仅仅删除文件不够——历史里还在。必须：

1. **立即通知知乎运营作废并更换 `secret_key`**（最重要，做这个）
2. 通知团队负责人
3. 考虑用 `git filter-repo` 清理历史（需要团队协调 force push）

历史清理很麻烦，**换密钥才是根本解决办法**。

---

**Q15：`git status` 显示大量 `node_modules` 文件**

`.gitignore` 里漏了 `node_modules/`。补上后：

```bash
echo "node_modules/" >> .gitignore
git rm -r --cached node_modules
git status   # 确认已消失
```

## 八、日常开发流程

### 每天开始工作

```bash
cd D:\ITEM\zhihu-app\web

# 1. 拉最新代码
git switch main
git pull

# 2. 如果 package.json 变了，重装依赖
npm install

# 3. 开新分支
git switch -c feat/your-feature

# 4. 启动开发服务器
npm run dev

# 5. 另开一个终端，跑测试监听
npm run test:watch
```

### 写代码时

| 场景 | 做法 |
| --- | --- |
| 不确定代码放哪一层 | 查 [01 文档的分层决策树](./01-架构设计.md#七分层决策树) |
| 不确定接口参数 | 查 [03 文档](./03-接口文档.md) 对应章节 |
| 签名相关问题 | 查 [04 文档](./04-签名机制.md) |

| 不知道怎么测 | 查 [05 文档 § 二](./05-测试文档.md#二测试分层与工具) |

### 提交前

```bash
# 一键跑完所有检查
npm run verify
```

这一条等于 `typecheck` + `lint` + `test`。全绿才提交。

```bash
# 看清楚要提交什么
git diff --cached --stat

# 确认没有误加敏感文件
git diff --cached --name-only | grep -iE "\.env|secret|credential"
# 应该没有输出

# 按 Conventional Commits 规范提交
git add src/utils/signature.ts src/utils/__tests__/signature.spec.ts
git commit -m "feat(sign): 实现签名六步法与黄金用例测试"

# 推送并开 PR
git push -u origin feat/your-feature
```

### 联调真实接口时

🔴 **牢记日配额限制：**

- 一次只调一个接口，不要写循环
- 每次调用的结果记录到 [05 文档的联调用例表](./05-测试文档.md#七接口联调用例)
- 失败先查文档，不要立刻重试
- 联调前和团队沟通，避免多人同时大量调用
