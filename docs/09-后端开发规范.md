# 09 · 后端开发规范（BFF 实现任务书）

> **这是一份完整的后端任务书，不需要阅读其他任何文档就能开工。**
>
> 你要做的事一句话：在 `server/` 目录下实现一个 Node.js BFF，
> 为 `platform/`（前端，已完成 UI，端口 5174）提供所有数据接口，
> 并负责向知乎 OpenAPI（`https://open.zhihu.com`）发起签名请求。
>
> 前端永远不直接请求知乎，签名在你这里算，`secret_key` 不出后端。

---

## 一、技术栈

| 项 | 选型 |
|---|---|
| 运行时 | Node.js 24.19.0 LTS |
| 框架 | Express 4 + TypeScript 5 |
| 数据库 | MySQL 8.0 |
| ORM | 直接用 `mysql2/promise`（不用 Sequelize/Prisma，避免抽象层隐藏 SQL 问题） |
| 鉴权 | `jsonwebtoken`（JWT HS256） |
| 加密 | Node 内置 `crypto`（不引第三方签名库） |
| 任务队列 | `bull` + Redis（用于异步推送计划到知乎，Redis 本地跑即可） |
| 定时任务 | `node-cron`（每日指标拉取） |
| 测试 | Vitest + MSW（`onUnhandledRequest: 'error'`，不打真实接口） |
| 端口 | 3000 |

> 如果环境没有 Redis，暂时用 `setImmediate` + 内存队列 mock 异步推送，
> 后面再换 Bull。第一阶段先把接口跑通比什么都重要。

## 五、签名实现

**两层哈希**：先 MD5，再 HmacSHA256，用 Node 内置 `crypto`，不引第三方库。

```typescript
// src/sign/zhihu.ts
import crypto from 'crypto';

const EXCLUDED = ['offset','limit','file','image',
                  'second_channel_id','X-Requested-With','signature'];

export function buildSignature(
  params: Record<string, unknown>,
  secretKey: string,
): string {
  const kvStr = Object.keys(params)
    .filter(k => !EXCLUDED.includes(k))
    .sort()                                            // ASCII 升序，不用 localeCompare
    .map(k => `${k}=${String(params[k])}`)             // 值不 URL-encode，中文原样
    .join('&');

  const md5 = crypto.createHash('md5').update(kvStr, 'utf8').digest('hex');
  return crypto.createHmac('sha256', secretKey).update(md5, 'utf8').digest('hex');
}

/** 自动注入 access_token + timestamp + signature */
export function injectSignParams(
  params: Record<string, unknown>,
  accessToken: string,
  secretKey: string,
): Record<string, unknown> {
  const withMeta = {
    ...params,
    access_token: accessToken,
    timestamp: Math.floor(Date.now() / 1000),   // 秒级
  };
  return { ...withMeta, signature: buildSignature(withMeta, secretKey) };
}
```

**Golden Vector（单测必须包含，用 Node crypto 已复算通过）**：

```
access_token = Db6j0Yq0eppBb
secret_key   = a735eb11da74123074675fa3522a90d1

参数（排序后拼接）：
access_token=Db6j0Yq0eppBb&channel_id=1462106336904909960&content_url=https://www.zhihu.com/market/paid_column/1550452094749851648/section/1590711798218661888&keyword=这是一个测试关键词&popularize_type=0&task_id=1443567656205545123&timestamp=1672899103

MD5       = 112f078ecdb75d76b38e4d9e661772bd
signature = 794a1d97ffdd4af53c7064d697d686e2da4177bc2ccdcb4168e2f829b0f5c579
```

容易踩的坑：

| 坑 | 正确做法 |
|---|---|
| 用 `encodeURIComponent` 编码值 | 值**不编码**，中文和 `://` 原样 |
| 时间戳用毫秒 | 秒级（10 位），`Math.floor(Date.now() / 1000)` |
| 签名字段名用 `sign` | 必须叫 `signature` |
| 以为有 nonce | **没有 nonce**，防重放只靠 timestamp |
| `second_channel_id` 也参与签名 | 它在排除列表里，**不参与** |

## 六、知乎 API 调用封装

```typescript
// src/zhihu/client.ts
import axios from 'axios';
import { injectSignParams } from '../sign/zhihu';
import config from '../config';

const zh = axios.create({ baseURL: config.zhihu.apiBase, timeout: 15000 });

export async function zhihuGet(path: string, params: Record<string, unknown> = {}) {
  const signed = injectSignParams(params, config.zhihu.accessToken, config.zhihu.secretKey);
  const res = await zh.get(path, { params: signed });
  return res.data;
}

export async function zhihuPost(path: string, body: Record<string, unknown> = {}) {
  const signed = injectSignParams(body, config.zhihu.accessToken, config.zhihu.secretKey);
  const res = await zh.post(path, signed);
  return res.data;
}
```

### 7.2 中间件

```typescript
// src/auth/middleware.ts
import jwt from 'jsonwebtoken';
import { Request, Response, NextFunction } from 'express';
import config from '../config';

export interface AuthUser {
  sub: number; role: 'boss'|'leader'|'member'; parent_id: number|null;
  username: string; display_name: string;
}

declare global {
  namespace Express { interface Request { user: AuthUser } }
}

export function requireAuth(req: Request, res: Response, next: NextFunction) {
  const token = req.headers.authorization?.replace('Bearer ', '');
  if (!token) return res.status(401).json(fail(40100, '请先登录'));
  try {
    req.user = jwt.verify(token, config.jwtSecret) as AuthUser;
    next();
  } catch { res.status(401).json(fail(40101, '登录已过期，请重新登录')); }
}

export function requireRole(...roles: AuthUser['role'][]) {
  return (req: Request, res: Response, next: NextFunction) => {
    if (!roles.includes(req.user.role))
      return res.status(403).json(fail(40301, '无权执行此操作'));
    next();
  };
}

function fail(code: number, msg: string) { return { code, data: null, message: msg }; }
```

## 八、分级数据隔离

**每一个列表/统计接口都必须调用这个函数，一个都不能漏。**

```typescript
// src/utils/scopeFilter.ts
import { AuthUser } from '../auth/middleware';

/**
 * 返回 SQL WHERE 片段和绑定参数
 * 用法：const { clause, bindings } = scopeFilter(req.user, 'owner_id')
 *       db.query(`SELECT * FROM plans WHERE ${clause}`, bindings)
 */
export function scopeFilter(user: AuthUser, ownerCol = 'owner_id') {
  switch (user.role) {
    case 'boss':
      return { clause: '1=1', bindings: [] };
    case 'leader':
      return {
        clause: `${ownerCol} IN (
          SELECT id FROM users WHERE parent_id = ? OR id = ?
        )`,
        bindings: [user.sub, user.sub],
      };
    case 'member':
      return { clause: `${ownerCol} = ?`, bindings: [user.sub] };
  }
}
```

**还要做：**
- `POST /team/members` 中，`parentId` 强制用 JWT.sub（忽略请求体里的值），
  防止 leader 把账号挂到别人组下。
- `PATCH`/`DELETE` 操作前，先查记录的 `owner_id`，确认在调用者可见范围内才允许。

## 九、统一响应格式

```typescript
// src/utils/response.ts
import { Response } from 'express';

export const ok = (res: Response, data: unknown) =>
  res.json({ code: 0, data, message: 'ok' });

export const okList = (res: Response, list: unknown[], total: number,

```

**JSON 序列化约定**（前端按这个解析，后端不能改）：

| 类型 | 格式 | 反例 |
|---|---|---|
| ID | 字符串 `"12"` | ~~数字 `12`~~ |
| 金额 | number 元 `1234.56` | ~~字符串 `"¥1,234.56"`~~ |
| 百分比 | number 小数 `0.15` | ~~`"15%"`~~ |
| 时间 | ISO 8601 `"2026-08-06T14:30:00+08:00"` | ~~Unix 时间戳~~ |
| 空值 | `null` | ~~`""` `0` `"-"`~~ |

⚠️ MySQL BIGINT 默认序列化成数字，**必须手动转字符串**，否则雪花 ID 精度丢失：

```typescript
// 简单处理：序列化时把所有 bigint 字段转 string
function serializeRow(row: Record<string, unknown>) {
  return Object.fromEntries(
    Object.entries(row).map(([k, v]) =>
      [k, typeof v === 'bigint' ? String(v) : v]
    )
  );
}
```

### 10.1 词占用校验（关键接口，前端失焦时调）

```
POST /api/v1/plans/check-keyword
Body: { channelId: "987...", keyword: "程序员接单" }

可用：{ code: 0, data: { available: true } }

占用：{ code: 0, data: {
    available: false,
    occupiedBy: "张**",        // 脱敏：保留首尾各一字，中间 **
    occupiedByMe: false,
    planId: null               // occupiedByMe=true 时才返回
}}
```

### 10.2 创建计划（异步推送流程）

```
1. 校验权限点 plan.create
2. 查 plans 表 UNIQUE(channel_id, keyword) → 已存在则返回 40901
3. INSERT plans (sync_status='local', owner_id=JWT.sub)
4. 立即 return 201 { code:0, data: { id, syncStatus:'local' } }
5. 异步（setImmediate 或 Bull 队列）：
   a. UPDATE plans SET sync_status='syncing'
   b. POST /alliance/api/popularize_plan（签名）
   c. 成功 → UPDATE SET sync_status='synced', zhihu_plan_id=...
   d. 失败 → UPDATE SET sync_status='failed', sync_error=...
6. INSERT audit_logs (action='plan.create', ...)
```

前端轮询 `GET /plans/:id` 的 `syncStatus` 字段显示同步状态。

### 10.3 每日指标写入（幂等）

```sql
INSERT INTO daily_metrics
  (project_id, channel_id, keyword, plan_id, owner_id,
   stat_date, impressions, clicks, conversions, earning, raw_json, fetched_at)
VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, NOW())
ON DUPLICATE KEY UPDATE
  impressions = VALUES(impressions),   -- 覆盖，不是 +=
  clicks      = VALUES(clicks),
  conversions = VALUES(conversions),
  earning     = VALUES(earning),
  raw_json    = VALUES(raw_json),
  fetched_at  = NOW();
```

定时任务每天 02:00 拉取 T-7 到 T-1（7 天），全部覆盖写。
`owner_id` 通过 `(channel_id, keyword)` 查 `plans.owner_id` 填充，
查不到则留 NULL 并写一条 WARN 日志（有站外绑的词，需人工认领）。

## 十一、安全红线（违反会导致安全事故）

1. `ZHIHU_SECRET_KEY` 不得出现在：前端代码、`.env`（非 local）、git 仓库、日志
2. 不得用 `VITE_` 前缀暴露任何 key
3. 生产 `NODE_ENV=production` 时签名必须在 BFF 算，不能有「前端代sign」的分支
4. 返回给前端的 signKey/secret 类字段**一律脱敏**（`****` 加末 4 位）
5. 接口有**日配额**：不写循环压测，定时任务有频率保护，单测一律 Mock
6. `audit_logs` 只 INSERT，不 UPDATE 不 DELETE
7. bcrypt cost=12，不可降低
8. `POST /team/members` 中 `parentId` 强制用 JWT.sub，不信任请求体
9. 新代码只用 v2 作品接口（v1 于 2026-08-25 下线）
10. 密码重置后旧 token 必须失效（jti 黑名单）

## 十二、分阶段验收标准

### Phase 1 验收

```bash
# 1. 正常登录返回 token
curl -X POST http://localhost:3000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"xxx"}'
# 期望: { code:0, data:{ token:"eyJ...", user:{...}, mustChangePwd:false } }

# 2. 无 token 访问受保护接口返回 401
curl http://localhost:3000/api/v1/auth/me
# 期望: { code:40100, ... }

# 3. 用 token 访问返回权限点
curl http://localhost:3000/api/v1/auth/me \
  -H 'Authorization: Bearer <token>'
# 期望: { code:0, data:{ role:"boss", permissions:["plan.create",...] } }

# 4. member token 访问需要 boss 权限的接口返回 403
# 5. Golden Vector 签名单测通过
```

### Phase 2 验收

```bash
# 1. 创建计划立即返回 201（不等知乎）
curl -X POST http://localhost:3000/api/v1/plans -H 'Authorization: Bearer <leader_token>' \
  -d '{"taskId":"...","channelId":"...","keyword":"测试词","landingUrl":"https://..."}'
# 期望: { code:0, data:{ id:"1", syncStatus:"local" } }，响应时间 < 200ms

# 2. 同一渠道同一词再创建返回 40901
# 3. member token 只能看到自己的计划（另一 member 的计划不可见）
# 4. leader token 看到本组所有成员的计划，但看不到其他组的
# 5. boss token 看到全部计划
```

### Phase 3–7 验收

- 所有列表接口：用 leader token 遍历，返回数据里**没有其他组的 owner_id**
- 收益数字：DECIMAL 序列化为 number，不带千分位，不带货币符号
- 所有 ID 字段：为字符串
- 知乎 API 调用：只在 `POST /metrics/sync` 和 `POST /plans/:id/retry-sync` 中触发，
  普通 GET 接口只读本地库
- 打包 / 运行时全文搜 `secret_key` 结果为空
- 所有创建/修改/删除操作都有对应的 `audit_logs` 记录
