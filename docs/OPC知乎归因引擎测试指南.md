# OPC 知乎归因引擎测试指南

版本日期：2026 年 9 月 13 日。测试分支：`codex/zhihu-attribution-test`。适用对象：负责功能验收和问题复现的协作者。

本次测试验证知乎模块的独占关键词、任务报价、报告归因、作品核验和应付对账。OPC 仍是聚合平台，知乎只是其中一个模块。先完成下面的隔离演练，再安排真实 Excel 的口径抽样；合成样本通过不等于生产验收完成。

## 1 获取代码和启动环境

准备 Git、Node.js 24.x、pnpm 9.15.0，以及已启动的 Docker Desktop（Linux 容器）。`docker version` 必须能同时显示 Client 和 Server；只看到 Client 或请求超时，先恢复 Docker 再继续。

首次获取代码，在自己选择的开发目录执行：

```powershell
git clone --branch codex/zhihu-attribution-test `
  https://github.com/Ashleymmy/zhihu.git zhihu-attribution-test
cd zhihu-attribution-test
pnpm install --frozen-lockfile
npm --prefix server ci
pnpm build
docker pull mysql:8.0
npm --prefix server run demo:attribution
```

已有仓库时，先保留自己的未提交改动，然后执行 `git fetch origin`，切换并跟踪 `origin/codex/zhihu-attribution-test`。不要将未提交工作直接覆盖掉。前端由 pnpm 管理，server 独立使用 npm，安装命令两条都要执行。

启动器每次创建全新的隔离 MySQL，运行增量迁移，模拟上游创建成功；使用真实应用接口、权限和业务服务。它不使用业务库的连接配置，也不需要真实知乎密钥。等待终端出现“OPC 知乎隔离演练已就绪”，再打开打印的地址。

| 角色 | 登录地址 | 账号 | 密码 |
| --- | --- | --- | --- |
| 管理员 | 终端中的 `/admin/login` | `admin` | `isolated_password` |
| 团长 | 同端口 `/leader/login` | `leader` | `isolated_password` |
| 达人 | 同端口 `/creator/login` | `creator` | `isolated_password` |

端口由系统分配，不固定为开发者电脑的 58407。`127.0.0.1` 指你自己的电脑，不能用于访问另一位同事的环境。三种身份可以依次退出后登录，也可以使用独立浏览器配置文件并排测试。

保留启动终端。输入 `q` 后回车或按 Ctrl+C 结束，启动器会删除本次临时数据库。日志、报表和 `session.json` 保留在终端打印的 `.opc-work/attribution-demo/<本次目录>/`。重新启动会得到新数据库、新端口和新的样本目录。

## 2 预置数据和正确入口

进入“知乎 → 归因与对账”，再选择“报告与归因”。页面地址以 `/admin/modules/zhihu/keywords` 为入口。不要把新模拟文件提交到“历史邮件 / Excel 导入”；该页用于旧链路及旧记录查询。

启动器已创建项目“知乎历史业务”、接入账号“知乎历史接入”、渠道“测试渠道”和任务“测试任务”。这两个“历史”名称来自空库初始化，它们在本次演练中均属于隔离库。

- “模拟独占词甲”和“模拟独占词乙”已由团长领取，分配给达人并声明使用。
- 代理给团长的任务报价为 15 元/单，团长给达人的报价为 13 元/单；两词共用同一任务报价。
- 新引擎从本次启动的上海业务日期进入“试算”模式；尚未导入报告、登记作品或确认应付。
- 两个绑定编号见关键词列表及 `session.json`。不要把关键词编号、绑定编号和归因编号混用。

报告目录提供两个文件：先用 `01-首次报告100单.xlsx`，完成首次对账后再用 `02-修订报告90单.xlsx`。每次启动请使用本次生成的文件，不要沿用以前演练的旧日期文件。

| 文件与关键词 | 搜索量 | 订单量 | 搜索转化率原值 |
| --- | --- | --- | --- |
| 首次报告 词甲 | 600 | 60 | 10 |
| 首次报告 词乙 | 400 | 40 | 10 |
| 修订报告 词甲 | 600 | 54 | 9 |
| 修订报告 词乙 | 400 | 36 | 9 |

表头依次为：日期时间、渠道名称、关键词、推广任务、风险判定、搜索量、订单量、搜索转化率（单位%）。风险判定为空，没有收益列。10 表示原表单位下的 10%；转化率仅用于展示，不参与计费。

## 3 首次导入和金额核对

1. 管理员打开“报告与归因”，选择“综合反馈报告（搜索量＋订单量）”，上传首次报告。
2. 点击“上传并预览”。应识别到 2 行，日期与本次启动日期相同，订单分别为 60、40，风险和来源收益显示未提供。
3. 点击“确认导入全部有效行”，等待处理后刷新。应形成 2 条归因结果，归属为同一团长及其达人，合计 100 单；不能出现平均分配或质量加权结果。
4. 分别登录三端核对金额及可见范围。首次作品尚未核验，此时应付对账不能确认。

| 项目 | 词甲 | 词乙 | 合计 |
| --- | --- | --- | --- |
| 代理应付团长 | 900 元 | 600 元 | 1,500 元 |
| 团长应付达人 | 780 元 | 520 元 | 1,300 元 |
| 团长毛差价 | 120 元 | 80 元 | 200 元 |

金额界面可能显示四位小数，例如 `900.0000`。代理成本是 1,500 元，不是两层相加后的 2,800 元。由于报告没有来源收益，代理毛差价应显示“无法计算”，不能推算成 500 元。达人只能看到自己的应付及报价，不能从页面或接口响应看到上游的 15 元报价和代理成本。

## 4 作品核验和逐层确认

1. 达人打开“作品与对账”，分别为两个绑定登记作品。演练可用 `https://example.com/demo/a` 和 `https://example.com/demo/b`，使用说明写“隔离模拟作品”。这里验证人工佐证流程，系统不会自动抓取这些链接。
2. 团长刷新作品列表，逐条点击“核验或争议”，填写“隔离演练核对关键词与执行人”，点击“通过核验”。管理员也有核验权限；核验自己的作品必须交给管理员。
3. 管理员在“试算与切换”中保持原起始日期，选择“启用对账确认”。依据填写“仅隔离库合成样本演练”，勾选核对项后保存。这个操作只用于隔离测试，不表示真实报告或生产环境已经验收。
4. 团长在“作品与对账”将账期起止日均设为本次业务日期，点击“按账期生成草稿”。应出现本人付款给达人的两条草稿，金额 780 元、520 元。选中后确认。
5. 管理员按相同账期生成自己应付团长的两条草稿，金额 900 元、600 元，再选中确认。代理层必须在团长对达人核对完成后确认。
6. 达人刷新，合计已确认应付应为 1,300 元。记录状态为“已确认”，不是已付款；公共余额、提现和实际打款不属于本次流程。

## 5 来源修订和差额调整

必须先完成上一节的首次确认，才能验证“保留旧账并生成调整”。如果在首次确认前导入修订，只能验证草稿更新。

1. 管理员上传并确认修订报告。它与首次报告属于同一账号、渠道、关键词和业务日期，不应新增另一份 90 单业绩。
2. “来源异常与修订”应出现两条不同值修订候选。核对当前来源后，分别选择候选并填写修订依据，接受修订；只上传文件不等于已接受新值。
3. 刷新归因与对账，当前有效订单合计为 90 单。原先确认的四条金额保留；按相同账期重新生成或查看调整草稿，不能覆盖旧记录。
4. 仍由团长先确认自己对达人的调整，再由管理员确认代理层调整。完成后两层净应付分别为 1,350 元和 1,170 元。

| 调整项 | 词甲 | 词乙 | 合计 |
| --- | --- | --- | --- |
| 代理应付团长调整 | −90 元 | −60 元 | −150 元 |
| 团长应付达人调整 | −78 元 | −52 元 | −130 元 |
| 修订后团长毛差价 | 108 元 | 72 元 | 180 元 |

重复上传或再次确认同一来源，不能继续累加订单或重复生成差额。可从归因详情追溯原文件、原始行、当前事实版本、绑定和报价；按业务日期取价，不按上传日期取价。

## 6 必测的异常和权限场景

在主流程完成后测试。需要修改样本时，另存副本，保留初始文件；不要在文件里添加计算公式或额外工作表公式。

| 编号 | 操作 | 应看到的结果 |
| --- | --- | --- |
| T01 | 重复上传同文件或仅改文件名 | 同值去重，订单与应付不翻倍 |
| T02 | 将词甲替换为未创建的新关键词 | 进入映射或归属异常，不能任意分到现有达人 |
| T03 | 风险判定填写“待上游说明” | 原文保留并暂停该来源对账，不自动认定有效或按比例扣除 |
| T04 | 保持订单为明确的 0；另做缺订单列的副本 | 0 与缺失区分；缺列不能按 0 元完成对账 |
| T05 | 给团长的达人发布 16 元/单报价 | 拒绝高于 15 元进价的倒挂报价 |
| T06 | 发布与现有版本重叠的报价 | 拒绝冲突，不覆盖已经生效的版本 |
| T07 | 对两个已用词申请释放或重新分配 | 拒绝，保留原商业归属 |
| T08 | 新建一个未使用词，由团队达人直接领取 | 团队达人不能领取公共库存；团长可领取并分配 |
| T09 | 标记某绑定作品有争议，再尝试确认应付 | 该绑定暂停确认，解除争议须有权限与依据 |
| T10 | 用达人身份直接请求管理接口或篡改项目 ID | 返回拒绝或无授权数据，不能泄露上游价格 |
| T11 | 旧“历史邮件 / Excel 导入”重复预览并打开明细 | 不出现 SQL 500；失败时不保留旧成功提示 |
| T12 | 新周期报告尝试走旧入口确认 | 日期边界阻止进入旧处理链，不能重复计量 |

并发 50 次领取、24 小时优先期边界、账号停用、Worker 恢复、空库和升级迁移由下节自动化覆盖。手工测试不能通过调本机时间替代这些测试。

## 7 自动化验证和问题反馈

在仓库根执行下列命令，保留真实输出与退出码：

```powershell
pnpm run verify:opc
npm --prefix server run build
npm --prefix server run test:attribution
npm --prefix server run demo:attribution -- --check
```

`verify:opc` 包含后端类型检查、纯核心构建、前端类型和构建，以及 OPC 隔离测试。`test:attribution` 使用一次性 MySQL，并在故障组创建 Redis。`--check` 只验证演练初始化和报表生成，随后自动回收；它不等于完整页面验收。

浏览器完整验收需要 Playwright 和已安装的 Edge。在 Windows PowerShell 的仓库根执行：

```powershell
npm install --prefix .opc-work/playwright --no-save playwright
$env:OPC_PLAYWRIGHT_MODULE = (Resolve-Path .opc-work/playwright/node_modules/playwright).Path
$env:OPC_BROWSER_CHANNEL = 'msedge'
npm --prefix server run test:attribution:ui
```

上述 Playwright 只安装到 Git 忽略的测试目录，不修改项目依赖。其他系统可使用已安装的 Chrome，并把 `OPC_BROWSER_CHANNEL` 设为 `chrome`。证据输出在 `.opc-work/attribution-ui/`，包括三端截图、HTTP 日志和 `result.json`。

提交问题时请附：测试分支及 `git rev-parse HEAD`、Node/Docker 版本、角色、项目与账号、业务日期、关键词/绑定/归因编号、使用的样本文件、操作步骤、预期与实际结果、请求状态码，以及截图或日志。不要附真实密钥、登录令牌或数据库密码。

常见排查：页面仍显示旧标题时强制刷新；找不到报告时查看本次终端打印的目录；有预览但无归因时确认是否点击了确认导入并刷新；不能确认时检查试算状态、首次核验、争议、缺价和逐层确认顺序；容器启动错误时先检查 Docker Server 状态。

## 8 本次交付验证记录

2026 年 9 月 13 日的交付检查：后端类型检查与构建、纯核心构建、前端 11 项类型检查及三端构建通过。归因测试中不依赖容器的 15 项通过，OPC 非数据库测试 3 项通过。
