## 这个项目是做什么的

我们要开发一个 **Web 端管理平台**，用来对接「知乎开放平台 - 知星河推广」的 OpenAPI。

用大白话说：知乎给我们开放了 31 个 HTTP 接口，可以创建推广计划、上传推广作品、
查数据报表、举报违规词等等。但这些接口只能用代码调用，运营同学没法直接用。
所以我们做一个网页界面，让运营同学在页面上点点填填，就能完成这些操作。

这个 Web 项目同时承担两个角色：

| 角色 | 说明 |
| --- | --- |
| **接口调试台** | 开发阶段用来验证每个接口能不能调通、签名对不对 |
| **业务管理后台** | 交付后给运营同学日常使用 |

后续还会开发微信小程序（`app/` 目录），届时会复用本项目的服务层设计。

## 三条必读的红线

这三条是项目的硬性约束，违反会导致安全事故或线上故障。

### 红线一：`secret_key` 绝对不能出现在前端代码里

`secret_key` 是签名私钥。一旦泄露，任何人都能伪造我们的身份调用接口，
消耗我们的日配额、甚至创建垃圾推广计划。

- ❌ 不要写在 `.vue` / `.ts` 文件里
- ❌ 不要写在 `.env` 里然后用 `VITE_` 前缀暴露（Vite 会把它打进产物）
- ❌ 不要提交到 Git
- ✅ 生产环境：签名必须在**后端服务**完成，前端只调自己的后端

详见 [01-架构设计.md](./01-架构设计.md) 的「安全边界」章节。

### 红线二：新代码只准用 v2 版接口

推广作品相关的 v1 接口（`/popularize_composition`、`/popularize_compositions`）
**知乎官方计划于 2026-08-25 下线**。

今天是 2026-08-03，距离下线只剩约 3 周。所有新代码直接对接 v2：

- ✅ `/alliance/api/popularize_composition/v2`
- ✅ `/alliance/api/popularize_compositions/v2`
- ✅ `/alliance/api/popularize_composition/v2/:composition_id`

### 红线三：接口有日配额，不要写循环压测

每个开发者账号**每日接口调用总次数**有上限（所有接口共享同一配额），
超限后当天会被禁止访问，整个团队都没法开发。

- ❌ 不要写 `for` 循环批量调真实接口
- ❌ 不要在 `watch` / `onMounted` 里无节流地请求
- ✅ 单元测试一律用 Mock，不打真实接口
- ✅ 联调时手动点，一次一个

## 术语表

文档里会反复出现这些词，先记住它们。

### 业务术语

| 术语 | 英文/字段 | 含义 |
| --- | --- | --- |
| 开发者 Token | `access_token` | 我们的身份唯一标识，每个请求都要带 |
| 签名公钥 | `secret_key` | 用于计算签名的密钥，**只在服务端使用** |
| 接口签名 | `signature` | 每个请求算出来的防篡改校验值 |
| 推广任务 | `task_id` | 知乎侧配置的推广活动，我们在其下创建计划 |
| 推广计划 | `plan_id` | 一个关键词对应一个推广计划 |
| 推广作品 | `composition_id` | KOC 在各平台（抖音/小红书等）发布的推广内容 |
| 一代渠道 | `channel_id` | 我们（代理商）自己的渠道 ID |
| 二代渠道 | `second_channel_id` | 我们下游代理的渠道 ID |
| KOC | Key Opinion Consumer | 关键意见消费者，即达人/博主 |
| 截流词 | 风险类型 1 | 他人在我们的作品评论区引流截胡用的关键词 |
| 搬运词 | 风险类型 2 | 他人抄袭搬运我们内容时使用的关键词 |
| 批量任务 ID | `batch_task_id` | 批量接口返回的异步任务号，用它轮询结果 |

### 技术术语

| 术语 | 含义 |
| --- | --- |
| 六层架构 | 本项目的代码分层方式，详见 01 文档 |
| 视图层 | `views/` + `components/`，用户看到的页面 |
| 服务层 | `services/`，一个函数对应一个接口 |
| 基础设施层 | `infra/`，Axios 实例、拦截器、签名注入 |
| DTO | Data Transfer Object，接口请求/返回的数据结构类型定义 |
| 幂等 | 同一个请求重复执行多次，结果和执行一次相同 |
| BFF | Backend For Frontend，为前端服务的后端，本项目用它做签名代理 |

## 遇到问题怎么办

按这个顺序自查，能解决 90% 的问题：

1. **搜文档**：先在 `docs/` 目录里全文搜关键词，大概率已经写过了
2. **看排错手册**：签名问题看 04 文档，环境问题看 07 文档
3. **对照 PDF**：接口参数有疑问，直接翻 `web/` 下的官方 PDF
4. **问人**：以上都无解再找同事，并把结论**补写回文档**

最后一步很重要。每个人踩过的坑都写回文档，团队效率才会累积。
