# 知乎官方计划数据接入核查

核查日期：2026-09-20。此记录优先于旧审核同步文档中对计划查询能力的描述。

## 当前结论

**尚未接通知乎官方全部计划的实时读取。** 不能把本次纠错当作全量同步已经完成。

仓库中的官方 `OpenApi开发文档（标准版）V1.4.17.pdf` 第 6 页说明单个创建计划 POST，第 7 页开始说明批量创建计划 POST。文档没有提供 GET `/alliance/api/popularize_plans` 的查询、分页、签名或返回数据契约。原实现仅在客户端注册了这一 GET 地址，没有对应契约，因此在请求上游之前就失败；即使补上随意猜测的契约，原任务也只处理第一页最多 100 条，并仅更新本地已有的计划。

截图里的知乎 211 条为官方计划统计；代理平台的 103 条来自当前项目和账号范围内的 `zh_keywords` 本地业务记录，其中包含待提交、失败记录。不能直接相减后认定缺失 108 条，也不能将本地记录全部改为成功来对齐数字。

## 已修正

- 关键词列表明确标注本地数据来源、范围和本地读取时间。官方总数返回 null，界面显示暂不可读取。
- 本地数量按待提交、提交中/结果待确认、取得官方计划 ID、失败、联测及待核实分别统计。汇总与列表使用相同的账号、项目、搜索和角色限制，与当前分页无关。
- 创建接口返回有效官方计划 ID 后，系统会把本地计划置为可分配，团长可以领取，管理员可以直接分发给团长、团队达人或独立达人；这表示已取得创建回执，不等于知乎审核通过或官方当前状态查询成功。
- 升级时会自动修复此前已经保存为 `synced + 官方计划 ID`、但本地仍停留在待核实的未分配关键词；刷新页面、领取或管理员分发都会触发同一幂等修复。已有绑定、作品、指标或收益记录的历史词不会被重新开放。
- 移除没有官方依据的 GET 端点注册和无效计划定时同步。手动同步返回明确的 50312 未接通错误，不再报告已入队；残留旧队列任务也明确失败，不写本地状态。
- 保留原有创建、领取、分发、归属和历史业务数据。没有修改线上数据库，也没有部署。

## 关键词页与推广作品页的关联修复

用户后续截图对比的是平台内的关键词页与推广作品页。两页原先分别读取 `zh_keywords` 和 `compositions JOIN plans`，导致已有作品但没有词库记录的历史计划没有出现在关键词页。

- 两页统一使用 `plans.keyword`，通过 `plans.id` 关联词库和作品。关键词页纳入当前权限范围内已有作品的历史计划，同一计划的多条作品只计一个关键词。
- 历史计划保留原归属，以只读形式展示，不自动加入可领取词库。优先使用已有词库账号关系；历史记录按唯一渠道映射或项目唯一账号识别，账号不明确时不跨账号展示。
- 两页支持按关键词搜索和相互跳转。作品页按每页 25 条分页，取消原先仅取前 100 条的展示限制；两页在可见时每 15 秒刷新本地记录。
- 这项修复解决平台内部两页的关联一致性，不代表已接通官方全量计划查询。没有线上官方账号数据的实时一致性验收结论。

## 完成官方实时读取还需要

由知乎提供或确认代理商账号可用的完整计划查询方式及授权，至少包括请求地址、方法、签名字段、分页、全部/有效/失效统计、官方计划 ID、账号和渠道范围、状态含义及调用配额。

取得依据后才能实现：按已授权账号请求官方数据、完整分页、按官方 ID 关联本地归属、官方数量与本地业务数量分开显示、展示官方读取时间，以及请求失败时清楚标记过期或不可用。涉及已有作品或收益的计划不可自动放入未领取词库。

当前浏览器工具没有已登录的官方页面，本地已检查的接入配置为测试凭据，故没有作出“已与线上 211 条一致”的验收结论。浏览器截图中的登录状态不能当作服务端长期可用的授权。

- 后端类型检查、前端类型检查与统一前端构建通过。
