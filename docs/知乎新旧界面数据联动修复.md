# 知乎新旧界面数据联动修复

## 修复范围

截图中的新版“关键词与团队”与“更多功能”里的旧页面保留各自的操作入口，但相关数据应使用同一计划、作品和目录记录。

本次在已有关键词关联改造上修复了以下断点：

| 问题 | 修复后行为 |
| --- | --- |
| 新版词库只包含新词及有作品的旧词，漏掉尚无作品的旧计划 | 当前项目和明确账号范围内的旧计划也显示，按原归属限制可见性，历史记录保持只读 |
| 新版作品审核只查 `zh_evidence`，旧推广作品存在 `compositions` | `/workbench/works` 汇总两个来源；按计划、执行人和完整作品链接关联，同一登记作品不重复计数 |
| 平台人工核验与知乎审核混在一起理解 | 新版分别显示两种审核。旧版作品页使用同一个知乎状态展示函数，并可跳转查看平台核验 |
| 作品同步缺少必填渠道、关键词，使用了错误分页参数 | 按渠道、关键词分组，以 `offset/limit` 完整分页，再按官方作品 ID 更新已有记录 |
| 上游转换丢弃可选审核字段 | 只保留实际返回的状态、审核状态、拒绝原因和分页信息；未提供时不虚构审核通过，也不覆盖已有结果 |
| 任务和渠道同步只读取一页 | 持续读取后续页；重复页、异常响应、缺页或请求失败报告失败，不假报完整同步 |
| 新版目录只显示名称，且停留页面时不会更新 | 显示知乎编号、任务单价、结算方式、状态、有效期和同步时间；可见页面每 15 秒更新，返回窗口、切换工作事项时也刷新 |
| 真实知乎创建成功后关键词一直停留在“待核实”，新旧页面没有分发入口 | 真实创建回执包含有效计划 ID 时自动开放未分配词；管理员可分发给团长、团队达人和独立达人，团长仍可领取后分发给团队达人 |

## 数据边界

- 旧作品按原所有者过滤，新平台核验按关键词绑定过滤；每次汇总都校验项目、账号访问权限。历史账号无法唯一确定时不猜测归属。
- 只展示并关联已有业务记录，不自动改写历史归属，也不把知乎审核通过转换成平台审核通过或财务确认。
- 官方任务单价仅供参考，成员结算仍使用已发布的定价规则。
- 官方完整计划查询仍未接通，见《知乎官方计划数据接入核查》。此次修复不能解释为已经抓取该官方账号的全部计划或全部作品；作品同步更新的是本地已登记且具有官方作品 ID 的记录。创建回执可用于本地领取和分发，不代表官方审核通过。
- 不需要新增数据库迁移。本次只修改本地代码，未部署线上，也未修改线上业务数据。

## 验证

- 临时 MySQL 的归因测试覆盖真实创建回执、旧卡住记录自动恢复、管理员向团长/团队达人/独立达人分发、团长领取及历史保护；同时覆盖 130 条旧作品分页、无作品历史计划、关键词修改、双来源关联去重、平台独立审核、账号歧义和成员隔离。
- 上游同步、契约和接口专项测试 52 项通过，覆盖第 101 条数据、必填同步参数、上游缺字段、请求失败、重复分页和可选审核字段保留。
- 前端单元测试 27 项通过；前后端类型检查、统一前端构建通过。
- 浏览器回归入口：`server/tests/attribution-ui/linkage.cjs`。使用临时数据库和真实前后端验证旧词、作品分页、两边审核展示、目录自动更新及手机页面；真实知乎请求被隔离。
- 浏览器回归已通过，截图保存在 `.opc-work/linkage-ui/`。
