# 网站管理角色与设备会话

本规则只适用于网站后端及统一 `/app/` 工作台，不改微信小程序的后端或账号库。

## 角色

| 角色 | 业务权限 | 管理账号 | 登录上限 |
| --- | --- | --- | --- |
| developer（开发者） | 全部业务、配置及开发工具 | 可创建管理角色，调整其他管理账号；不能修改自身角色或停用自身 | 不限 |
| admin（管理员） | 原管理员权限，数据库工具改由开发者使用 | 可创建和管理 operator，不能操作同级或 developer | Web 1 + 移动 1 |
| operator（运营管理员） | 关键词、计划、作品、定价、团长及达人运营 | 不能创建管理账号或修改同级以上账号 | Web 1 + 移动 1 |
| leader / creator | 原团长 / 达人权限 | 保留原业务范围 | Web 1 + 移动 1 |

运营管理员没有接入密钥、接入配置、财务报表导入、结算确认、提现付款或归因引擎切换权限。原 admin 的运营/财务岗位限制继续有效。角色代码采用 `operator`，角色归一化兼容 `opreater` 拼写。

网站“角色与账号”页面提供管理账号创建、角色/岗位调整和停启用。临时密码仅在创建响应中显示，首次登录引导到“账号安全”修改密码。密码重置在“团队与成员”中按角色层级控制。角色变化、停用、重置密码及自己修改密码会撤销该账号所有设备会话。

## 设备规则

- 每个非开发者账号最多保留一个 Web 会话和一个移动浏览器会话。新登录立即替换同类别的旧会话，另一类别不受影响。
- 浏览器首次访问生成随机客户端 ID，保存于同源 localStorage。每个 API 请求及刷新请求通过 `X-Client-Id` 发送 ID，服务端保存 SHA-256 摘要。不同浏览器、隐私窗口或清理存储后视为不同客户端。
- 服务端依据 User-Agent 区分 Web / 移动类别，忽略请求体里的设备类型。这是浏览器客户端识别，不能作为物理设备或不可伪造的硬件身份认证。
- 登录与刷新锁定同一用户行，避免并发登录突破上限。访问令牌携带会话 ID，每次鉴权检查当前账号状态、角色、客户端摘要和会话有效性。退出立即撤销该会话；重放刷新令牌会持久撤销其整个会话。
- 网站现用 HTTP，刷新 Cookie 为 HttpOnly + SameSite=Lax；收到 HTTPS 请求时设置 Secure。

## 升级与初始账号

启动迁移运行 `schema/extensions/003_roles_device_sessions.sql`：扩展角色枚举、插入角色记录、创建 `login_sessions`，撤销旧刷新令牌。升级后已有用户需要重新登录一次；旧访问令牌缺少会话 ID，不能继续访问。业务数据不迁移，原 admin 密码和角色不改变。

首次创建开发者及运营账号可在部署容器中运行以下命令。输出含随机临时密码，应重定向到权限为 0600 的文件，禁止提交到仓库或写入公开日志：

```sh
umask 077
node dist/scripts/provision-management.js developer developer 开发者 > /protected/developer.json
node dist/scripts/provision-management.js operator operator 运营管理员 > /protected/operator.json
```

该脚本拒绝同名现有账号，不会重置密码或提升已有账号权限。后续由开发者在网站管理账号。

应用回滚不需要恢复业务库。旧版本不识别新管理角色，回滚后使用原 admin 登录；新增角色账号在重新部署支持本规则的版本后恢复使用。上线回滚会临时撤销本版本的设备约束，应优先修复前滚。

## 验证

`server/tests/attribution/roles-device-sessions.spec.ts` 在独立 MySQL 8 中验证各角色的两类会话、并发登录、开发者豁免、客户端绑定、刷新重放、退出、旧令牌失效、角色越权和改密撤销。`engine.spec.ts`、`claimed-composition.spec.ts` 继续覆盖业务和领取关键词后的作品登记。
