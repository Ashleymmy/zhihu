# 推广计划修复同步说明

## 修复内容

### 1. 创建页渠道校验

文件：`platform/src/views/dashboard/ZhihuPlansView.vue`

渠道下拉框绑定的是 `form.channel_id`，但表单校验字段原来写成了 `channelId`。现已统一为 `channel_id`，选择渠道后不会再误报“请选择渠道”。

### 2. 知乎推广计划同步 payload

文件：`server/src/jobs/pushPlan.ts`

本地数据库字段 `landing_url` 现在映射为知乎接口要求的 `content_url`。发送给知乎的字段仅保留：

```text
task_id
channel_id
content_url
popularize_type
keyword
second_channel_id（有值时才发送）
```

不再把本地管理字段 `landing_url`、`name`、`daily_budget` 直接发送给知乎。

### 3. 失败计划重试

文件：`platform/src/api/plans.ts`、`platform/src/views/dashboard/CampaignsView.vue`

同步状态为“同步失败”的计划现在会显示“重试同步”按钮，调用既有接口：

```text
POST /api/v1/plans/:id/retry-sync
```

点击后计划会重新进入异步同步队列；稍后刷新列表确认最终状态。该操作不会输出或修改任何 token、密码或密钥。

## 验证结果

- 后端 `npm.cmd run typecheck`：通过。
- 后端单元测试：10 个测试文件、22 个测试通过。
- 前端 `npm.cmd exec -- vue-tsc --noEmit`：通过。
- 完整 Vite 构建在当前 Windows 环境写入 `node_modules` 缓存时被 `EPERM` 阻塞，未发现 TypeScript 编译错误；建议在云端或本地解除依赖目录锁定后执行 `npm run build`。

## 云端同步建议

1. 云端 `/root/zhihu` 先确认工作区已有未提交改动，不执行 `reset`、`clean`、`stash` 或覆盖。
2. 执行 `git pull --ff-only origin main`。
3. 前端执行 `cd /root/zhihu/platform && npm run build`，将新 `dist` 内容按现有发布流程切换到 `/var/www/zhihu-platform`；静态前端更新不需要 reload Nginx。
4. 后端执行 `cd /root/zhihu/server && npm run build`。只有在用户单独批准后，才重启 BFF/worker 服务使 `pushPlan.ts` 生效。
5. 部署后验证：创建页渠道校验、创建新计划、失败计划“重试同步”、现有登录和其他页面回归。
