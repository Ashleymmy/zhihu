# 小程序注册短信验证：代码准备与启用

本期范围：新用户在小程序注册前验证手机号；继续使用现有网站账号库、微信绑定和邀请归属。代码准备阶段默认关闭，不发送真实短信，不部署、不上传体验版。

## 已实现

- 微信签名网关新增 `GET /core/auth/registration-policy` 和 `POST /core/auth/registration-code`。发送参数只接受 `phone`、`inviteCode`；身份只取可信网关上下文，禁止客户端指定接收身份、签名或模板。
- `/core/auth/register` 增加 `smsCode`；开关开启后服务端必填并验证，不能靠旧客户端或隐藏表单绕过。规则读取失败时小程序阻止提交并提供重试，不默认当作无需验证。
- 6 位随机数字（允许前导零），有效期 300 秒。同一手机号连续发送间隔至少 60 秒；每个微信每个自然分钟最多一次、每日 10 次；每个手机号每日 5 次；全站每日默认 100 次，可配置。每日按北京时间计数。这里统计发送尝试，供应商超时/失败不返还额度，避免重复计费。
- 每次发送前验证邀请码及已有账号/微信，发送不消耗邀请名额；已有账号按原账号密码登录。短信 `Code=OK` 才标记可用，HTTP 200 本身不能作为成功；SDK 自动重试关闭。
- 临时表只存手机号的 HMAC、可信微信身份哈希及验证码的 HMAC，不存明文手机号/验证码。错误验证最多 5 次，失败次数即使请求被拒绝也提交；重发替换旧挑战。程序没有生产“固定验证码”或模拟发送开关。
- 验证成功后，消费验证码、创建用户、消费邀请及绑定微信属于同一注册事务；提交前再次检查验证码期限和状态，失败全部回滚。验证消费失败不会留下半注册账号。
- 新注册验证通过写入 `users.phone_verified_at`；网站成员列表、小程序个人资料分别展示手机号验证。微信绑定不代表手机号验证或实名认证。管理员在任一成员修改入口换号码会清除验证时间；不改号码则保留。
- 验证码请求沿用小程序请求监控，只记录路由、状态码和耗时，不记录验证码、请求体或 SDK 原始异常。

## 兼容边界

本期没有改网站的可选联系方式规则，也没有开通短信登录、短信找回密码、老账号自助补验或手机号换绑。网站填入的号码、历史小程序号码、管理员录入的号码均为“未验证”；账号密码绑定微信后仍未验证。手机号不能凭一次收码自动合并账号或替代密码绑定已有账号。

这是一项“小程序新注册”的验证要求，不是“所有使用小程序的人必须完成手机验证”的准入门槛。以后需要全员验证时，应单独增加已登录补验流程，并明确哪些业务要求已验证，不能直接把历史号码标成已验证。

## 配置与控制台核对

2026-10-02 用户确认控制台验证码可正常收取。控制台核对：签名完整名称为“芜湖星火计划文化传媒”，状态可用正常；模板 `SMS_338995644` 审核通过、状态正常，正文为“您的验证码为：${code}，请勿泄露于他人！”，变量 `code` 仅数字，支持 4—6 位。模板没有声明有效期；注册页明确提示后端有效期为 5 分钟。控制台试发成功不等于应用容器已获得 API 发送权限。

部署时追加 `deploy/compose.sms.yaml`，通过 `SMS_ENV_FILE` 指向服务器上的独立受限文件；Compose 会保留原应用环境文件并追加短信配置，避免把短信密钥传给数据库、Redis 或提交到仓库。最小权限策略见 `deploy/sms-send-only-policy.json`。既有实例角色为 `studio-test-ecs-role`；启用前需要确认该角色具有 `dysms:SendSms` 权限，并在应用容器内验证 IMDSv2 临时凭据可用。

| 变量 | 配置 |
| --- | --- |
| `SMS_REGISTRATION_ENABLED` | 准备期 `0`；启用为 `1`；其他值拒绝服务，避免拼写错误静默绕过 |
| `SMS_SIGN_NAME` | 已完成报备的完整签名名称 |
| `SMS_TEMPLATE_CODE` | 审核通过并核对内容后的模板 CODE |
| `SMS_VERIFICATION_SECRET` | 独立的至少 32 字符随机密钥；用服务器 `openssl rand -hex 32` 生成并直接写服务器受限环境文件，不经仓库或聊天 |
| `SMS_DAILY_LIMIT` | 每日发送尝试硬上限，默认 100，试发阶段建议 10；可设 1—10000 |
| `ALIBABA_CLOUD_ECS_METADATA` | ECS 实例 RAM 角色名；默认凭据模式，强制 IMDSv2 |

RAM 角色仅授予 `dysms:SendSms`，不需要管理资质、模板或其他云资源。若当前环境无法使用实例角色，可在服务器环境注入独立 RAM 用户的 `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET`；临时凭据另带 `ALIBABA_CLOUD_SECURITY_TOKEN`。凭证从不传给小程序，不使用主账号密钥。

```json
{"Version":"1","Statement":[{"Effect":"Allow","Action":["dysms:SendSms"],"Resource":"*"}]}
```

## 部署与开通顺序

1. 备份数据库；按正常发布流程安装 `server/package-lock.json` 依赖并构建，运行迁移 `009_sms_registration.sql`。迁移不修改任何现有用户的验证状态。迁移有 MySQL DDL，请使用常规备份流程；不要在迁移部分失败时直接反复执行 ALTER。
2. 先部署后端（开关 0），再上传含验证码表单的小程序，确认体验版使用该包并可获取注册规则。网站构建中包含手机号验证标签。
3. 待签名报备结束、模板内容及 RAM 权限确认后，将环境变量显式传入应用容器。仅写入宿主机 env 文件而没有 Compose `environment` / `env_file` 透传不会生效；本次没有改线上 Compose。
4. 由负责人选择试发窗口和本人手机号，开关设为 1、日额度设为 10，重建应用容器。使用有效邀请在真机体验版测试一次发送、错误码、正确码、重登及网站显示。检查运营商实际送达；API 接受不代表手机已收到。
5. 确认各运营商送达及已上传客户端可用后安排正式发布；旧版客户端注册会收到升级/填写验证码提示。既有账号密码登录和微信登录保持原规则。
6. 开通后追加人工测试：有效/错误/过期/重发/并发、手机号与微信换人、改号清除验证状态、邀请失效、配额耗尽、发送失败和网络响应丢失。

若供应商异常，启用状态下应暂时阻止新注册，不能自动退回无验证注册。只有负责人明确接受重新允许未验证注册时才将开关改回 0；此前已验证的用户信息保留。老账号自助补验、短信找回密码留作后续独立需求。
